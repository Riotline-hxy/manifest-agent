# 显伴 · 小光：交接说明（给 GPT 讨论 agent 设计用）

写于 2026-10-26。来源是我（Claude）这几轮实际做过、测过的事。「未验证」的地方都标了。**没有放任何密钥。**

## 1. 项目是什么

显化（Manifest）+ 个人 agent，对标 Meta Muse，差异化是「显化陪伴」，不是通用助理。小光的定位一句话：

> 小光是你的显化陪伴，只帮你把「想成为的人」收成今天能走的一小步，不做万能助理。

会议（10-22）定的范围：五个分区（画像 / 计划 / 灵感 / 日常主动交互 / 记录与蜕变报告）、RAG + 每用户独立存储、不做子 agent、主动消息用定时任务、报告要有惊喜感。截止 11-10，目前是组内每周推进阶段。

材料在仓库里：`meeting.txt`、`creative/onboarding-and-scenes-v0.1.md`（8 题建档、4 个灵感场景、主动问候文案、惊喜规则，字段已锁）、`docs/三方向方案.md`（创意/技术/UI 总方案）。

## 2. 现在有什么（已部署：https://manifest.noryx.cn，分支 `claude/v1`，PR 已开）

技术栈：Python 标准库服务 + SQLite + 原生 JS，无第三方依赖。模型走 ModelFlare 中转站（OpenAI 兼容），默认 `gpt-6.1-sol`，`reasoning_effort=low`。

| 模块 | 文件 | 做了什么 |
|---|---|---|
| 账号与隔离 | `demo/core/auth.py`、`store.py` | PBKDF2 密码；服务端会话 + HttpOnly cookie；用户 id 只来自会话；每用户一个 SQLite（`data/u/<uid>/mind.db`）；体验账号预置 12 天示例，可原地转正 |
| Agent 循环 | `demo/core/agent.py` | 单 agent，流式输出，7 个工具，最多 4 轮工具调用；人设提示词在 `PERSONA` |
| 记忆 | `demo/core/store.py`（检索）、`memory.py`（写入） | 核心块每轮注入；档案记忆用 SQLite FTS5，中文字二元组分词，BM25 × 时间衰减 × 类型权重取前 6；写入管线参考 mem0 的 ADD/UPDATE/DELETE；模型的推测存为 `guess`，要用户点「对」才算事实 |
| 灵感场景 | `demo/core/scenes.py` | 4 个场景（说清想要的 / 三分钟感恩 / 短冥想 / 七步轻走）是服务端步骤状态机，每步等回答，结束按创意稿写入记忆或计划 |
| 主动消息 | `demo/core/scheduler.py` | 后台线程每 10 分钟扫一次；空闲阈值（12/24/60h）、23:00–08:00 静默、上一条未读不再发；文案由模型按记忆生成，失败用模板 |
| 报告 | `demo/core/report.py` | 事实和「惊喜句」由规则从数据算出，模型据此写一段信；失败用模板 |
| 前端 | `demo/public/` | 五个分区；对话是一条持续主线；Emotion Ball 球形形象（`orb.js` 适配）；记忆/活动抽屉；报告可存 PNG |
| 测试 | `demo/tests/test_api.py` | 22 个端到端测试，用脚本化假模型跑真服务器 |
| 模型对比 | `demo/bench_models.py`、`docs/bench-2026-10-26.json` | 5 个模型各 10 次 |

工具集：`search_memory`、`remember`、`add_step`、`complete_step`、`log_good_news`、`log_lazy_day`、`start_scene`。小光的表情不由模型选，而是服务端按执行了哪个工具决定（完成小步→庆祝，好消息→开心……）。原因：`gpt-6.1-sol` 在有 `set_mood` 工具时有一次只调工具、不说话，白白多一轮。

## 3. 实测过的事实（可以当依据）

- 中转站支持流式、工具调用；**不支持 `/v1/embeddings`**（404 `endpoint_not_enabled`）。所以检索只能是词法的。
- `gpt-6.1-sol` 只接受 `reasoning_effort` 为 low/medium/high/xhigh/max，`none`、`minimal` 会 400。
- 一次完整回复通常是两轮模型调用（选工具 + 说话）。我在服务器上单轮测到 7–29 秒，波动很大；本地测到 5–13 秒；公网实测一次聊天 28.6 秒（含工具）。**慢是现在最明显的体验问题。**
- 模型对比（10 次/个，样本小，只看趋势）：

| 模型 | 首响应 p50 | 最慢 | 工具选对 |
|---|---|---|---|
| gpt-6.1-sol | 5.2s | 13.9s | 9/10 |
| glm-5.3 | 2.9s | 9.6s | 10/10 |
| deepseek-v4-flash | 3.4s | 4.7s | 8/10 |
| deepseek-v4-pro | 4.1s | 10.1s | 8/10 |
| glm-5.3-flash | 6.1s | 15.6s | 9/10 |

- 线上验证过：两个账号互相看不到数据；无 cookie 401；跨站 POST 403；伪造 user_id 无效；真实对话触发了 `log_good_news`。

## 4. 已知问题与没验证的地方（讨论时重点）

1. **延迟**：两轮调用 + 中转站抖动。可考虑的方向：让模型在同一轮里既说话又调工具；工具在后台异步执行；换更快的模型；对简单输入跳过工具轮。没试过。
2. **记忆写入管线的真实效果证据不足**：测试用的是假模型。真实运行里，有一次抽取返回空，另一次成功写入了一条。没做系统评估，不知道召回/误记率。
3. **检索不懂同义改写**（「早睡」vs「十一点前上床」）。管线写入时额外给模型看最近 8 条记忆来弥补去重，检索本身没解决。
4. **人设提示词没经过严肃迭代**。语气（短句、不鸡血、先接情绪）是我按 PDF 和创意稿写的，没做过对比测试或人工评分。工具触发的边界（什么算「好消息」、什么时候该开场景）基本靠模型自己判断。
5. **没做心理安全处理**：用户如果说出明显的低落或危机内容，现在没有专门的检测或转介逻辑，完全靠模型自己。这个产品涉及「自我认知」，我认为应该讨论，但没动。
6. **主动消息**的内容只用了「最近记录 / 待办小步 / 愿景」三类线索，没有根据用户的习惯时间或情绪调整；也没有真实推送，只在网页里出现。
7. **推测确认卡片**：目前最多每轮一条推测，用卡片确认。没验证用户是否愿意点，也没验证推测质量。
8. **前端**：桌面端我逐页看过截图；手机端只验证了对话页、布局无横向溢出。灵感场景卡片、报告弹窗在手机上我没有截图复核。
9. 体验账号创建限流用了登录失败的计数器来凑，不够干净（`routes.py` 里的 `guest`）。
10. 旧版几个临时 `user_id` 的数据没有迁移，只在服务器备份里：`/opt/manifest-agent/backup-20261026-191920`。

## 5. 适合拿去和 GPT 讨论的设计问题

- **人设与对话策略**：怎样在「不催、不鸡血」和「真的推动用户做一小步」之间平衡？什么时候该问、什么时候该只听？
- **记忆**：什么值得长期记？推测和事实怎么分层？要不要加「记忆整理 / 遗忘」（比如晚间整理，会议原话提到过类似想法）？怎么评估记忆质量？
- **主动性**：触发信号该有哪些（时间、情绪、完成度、冷落程度）？怎样让主动消息「值得打扰」又不烦人？
- **显化方法的产品化**：七步目前只做到「场景」层面，没做成连续多日的旅程。要不要设计成有节奏的 7 天/21 天路径？
- **报告的惊喜感**：现在是规则 + 模型润色，惊喜点有限（高频词 / 慢下来仍完成 / 第一天 why 的反差）。还有什么更有分享欲的表达？
- **评估**：怎么给「陪伴感」「不说教」「记忆准确」做可重复的自动评估？现在只有工具选对率。
- **延迟与成本**：怎么把一次回复压到 3 秒以内，又不丢工具能力？
- **安全与边界**：低落、危机、依赖性（用户过度依赖）的处理策略。

## 6. 怎么跑

```bash
cd demo
echo "MODELFLARE_API_KEY=你的key" > .env     # 已在 .gitignore 里，别提交
python server.py 8765                         # http://127.0.0.1:8765 ，点「先体验一下」
python -m unittest discover -s tests -v       # 不消耗额度
python bench_models.py                        # 需要 key
```

部署：`bash deploy/deploy.sh`（会先在服务器备份，回滚命令在脚本末尾）。服务器 `/opt/manifest-agent`，systemd 服务 `manifest-agent`，密钥在服务器 `.env`。
