## 1. 创意：能做什么

**一句话**：小光是你的显化陪伴，只帮你把「想成为的人」收成今天能走的一小步，不做万能助理。

**和 Muse 的差别**：Muse 是通用个人 agent，帮你办事（订票、比价、回邮件）。显伴只陪一件事：自我探索和慢慢靠近理想的自己。我们借 Muse 的交互方式，不借它的功能范围。

**目标用户**：想改变、但常卡在「坚持」上的学生和年轻职场人。他们不缺目标管理工具，缺的是一个记得自己、不催、不评判的陪伴者。

**显化七步怎么落到功能里**（出自《Manifest: 7 Steps》）：

| 七步 | 在产品里 |
|---|---|
| 澄清 | 8 题建档写入「最想靠近什么、为什么」；灵感场景「说清想要的」 |
| 信念 | 记忆分成「你说的」和「小光猜的」，猜测要你点「对」才算数；七步场景里补一句「我配得上，因为……」 |
| 感受 | 短冥想：4-4 呼吸六轮，再问「意图实现时身体哪里先放松」 |
| 行动 | 计划只放 5 分钟能开始的小步，对话里一起定，完成得光点（萌芽→微光→小光→星光） |
| 感恩 | 输入框左边的星星一键记好消息；「三分钟感恩」场景 |
| 释放 | 偷懒日：不清零任何东西；七步场景里写下可放下的执念 |
| 见证 | 10 / 30 天蜕变报告：小光写的一段话 + 一条「你可能没注意到」 |

**五个分区**（会议定的）：对话 · 画像 · 计划 · 灵感 · 蜕变。

**日常路径**：首次 8 题建档（约 2 分钟）→ 之后每天：主动问候或自己来聊 → 定一小步 / 记好消息 / 做一个灵感场景 → 积累成报告。

**几个刻意的取舍**
- 偷懒日不清零：会议和 PDF 都强调「三天打鱼两天晒网也能慢慢靠近」。
- 报告不是统计表：数字放在下面，上面是一段话和一条惊喜。惊喜按创意稿 §D 的规则从真实数据算出（好消息高频词 / 休息了但还在走 / 第一天的 why 和现在的反差），模型只负责润色，不允许编造。
- MBTI、星座只是好玩，提示词里写明不用来判断人。

## 2. 技术：怎么落地

### 架构

```
浏览器 (原生 JS)                       Python 标准库服务 (无第三方依赖)
 ├ 对话 SSE 流 ───── POST /api/chat ──▶ agent.chat()
 │                                       1 检索记忆  store.search()  (FTS5)
 │                                       2 组装提示词 人设+七步+核心记忆+检索结果
 │                                       3 流式调用模型，带工具   ◀─▶ ModelFlare (OpenAI 兼容)
 │                                       4 执行工具 → 写本用户的库 → 再回到模型（≤4 轮）
 │                                       5 后台：记忆写入管线 memory.extract_and_apply()
 ├ 灵感场景 ──────── /api/scene/*  ───▶ 服务端步骤状态机，每步等用户回答，结束按规则写入
 ├ 报告 ─────────── /api/report    ───▶ 规则算事实与惊喜 + 模型写信（失败用模板）
 └ 其他 REST                            调度线程：每 10 分钟检查谁该被主动问候
                                        data/auth.db           账号、会话
                                        data/u/<uid>/mind.db   每个用户一个独立 SQLite
```

### 用户系统与隔离（上一版最大的缺口）

- **注册 / 登录**：密码用 PBKDF2-SHA256（20 万次迭代，每人独立盐）；会话 token 随机 32 字节，库里只存它的 SHA-256。
- **Cookie**：HttpOnly + SameSite=Lax，HTTPS 下加 Secure；前端脚本读不到。
- **身份只来自会话**：没有任何接口接受客户端传的 user_id。`?user_id=别人` 会被忽略（有测试）。
- **物理隔离**：每个用户一个 SQLite 文件。打开存储的唯一方式是 `Store(uid)`，uid 只能来自已验证的会话。
- **其他防护**：跨站 POST 校验 Origin；登录失败按 IP 和用户名限流；静态文件防路径穿越；JSON 体 64KB 上限；HTML 带 CSP。
- **体验账号**：「先体验一下」会建一个真的独立账号并预置 12 天示例，评委之间互不影响；之后注册可原地转正，数据保留。
- **数据可携带**：画像页可导出自己全部数据。

### Agent

- **单 agent + 工具调用**，不做子 agent（会议结论）。工具 7 个：`search_memory`、`remember`、`add_step`、`complete_step`、`log_good_news`、`log_lazy_day`、`start_scene`。
- 表情不占模型轮次：由服务端根据执行了什么工具决定（完成小步→庆祝，好消息→开心），通过 SSE `mood` 事件驱动小光的球。
- 模型失败时回复诚实的降级文案，不伪造回答。

### 长期记忆（参考 mem0 和 Letta/MemGPT 的成熟方案）

- **分层**：核心块（画像、愿景、边界、待做小步）每轮都放进提示词；档案记忆可检索。这是 Letta/MemGPT 的 core / archival 分层。
- **检索**：中转站没有 `/v1/embeddings`（实测 404 `endpoint_not_enabled`），所以用 SQLite FTS5 做词法检索。中文按**字二元组**切分（「自信」能命中「更自信地表达」），BM25 相关度 × 时间衰减 × 记忆类型权重，取前 6 条。每条回复下有「参考了 N 条记忆」，点开就能看到具体是哪几条。
- **写入**（mem0 的流程）：每轮对话后，模型从这轮里抽取候选事实，对照已有相关记忆决定 ADD / UPDATE / DELETE / 不动，避免越记越重复。只能改动给模型看过的记忆；每轮最多一条推测。
- **自述与推测分开**：推测写成 `guess`，在对话里以确认卡片出现，用户点「对」才进入可检索的事实。画像页可改、可忘掉（真删，含索引）。
- **以后升级**：换支持 embeddings 的服务后，在 `store.search()` 加一路向量召回再合并排序即可，接口不变。

### 主动消息

后台线程每 10 分钟扫一次。规则：空闲超过阈值（多一点 12h / 刚好 24h / 少一点 60h / 关闭）、不在 23:00–08:00、上一条还没看就不再发。内容由模型根据这个人的记忆写，失败用创意稿 §C 的模板。演示时可以在灵感页或活动抽屉里「现在演示一次」。

### 模型选择与评估

默认 `gpt-6.1-sol`，`reasoning_effort=low`（实测 `none`/`minimal` 不被支持）。`demo/bench_models.py` 在同一中转站、同一套人设和工具上测了 5 个模型。5 类输入（好消息 / 完成小步 / 想偷懒 / 想冥想 / 普通倾诉）× 2 轮 = 每个模型 10 次：

| 模型 | 首个响应 p50 | 最慢 | 工具选对率 |
|---|---|---|---|
| gpt-6.1-sol（默认） | 5.2s | 13.9s | 9/10 |
| glm-5.3 | 2.9s | 9.6s | 10/10 |
| deepseek-v4-flash | 3.4s | 4.7s | 8/10 |
| deepseek-v4-pro | 4.1s | 10.1s | 8/10 |
| glm-5.3-flash | 6.1s | 15.6s | 9/10 |

原始数据在 `docs/bench-2026-10-26.json`。样本少（每个 10 次），只能看趋势。会议说「优先国内模型」：glm-5.3 在这组测试里又快又准，切换只需改 `config/llm.json` 的 `model`。一次完整回复要两轮模型调用（先选工具、再说话），所以用户感受到的延迟大约是表里数字的两倍；界面在等待时用球的表情和「正在想 / 想起了 3 件事」的状态让等待可见。

### 测试与部署

- `python -m unittest discover -s demo/tests`：22 个端到端测试，用脚本化的假模型跑真服务器。覆盖：未登录 401、两个用户互相看不到数据、伪造 user_id 无效、跨站 POST 拒绝、Cookie 标志、密码不明文、建档字段、每个灵感场景都有写入、偷懒不清零、检索的二元组与猜测过滤、工具循环、模型失败降级、记忆写入管线、主动消息规则、报告惊喜。
- 部署：服务器 `/opt/manifest-agent`，systemd `manifest-agent` → `127.0.0.1:18765`，Caddy 反代 HTTPS。密钥只在服务器 `.env`（600 权限），不进仓库。

## 3. UI：用户体验

**参考对象**
- **Grok Bot**：一个有表情、会看着你的球形伙伴。小光的形象用 Emotion Ball 表情引擎（sam70361/aora-bot），跟随鼠标注视，状态有思考、检索记忆、回复中、开心、庆祝、疲惫等。
- **Muse**：一条永远延续的主对话；头像下一行写它正在做什么，点开是活动记录和「接下来打算做的」；推测用结构化的确认卡片；记忆可见可改；主动消息频率可调。

**视觉**：白底黑字，唯一的饱和色是伙伴自己的颜色（建档时选柔光 / 星尘 / 水墨 / 几何）。只有小光出现的地方是深色舞台：对话顶栏、画像卡、报告封面，让「它」成为页面上唯一的主角。好消息用五色手绘小星星，这点来自《好消息》App 的少量手作感。

**分区**：宽屏左侧导航 + 中间主区 + 右侧「今天」（今天的一小步、快速记录、光点、小光在做什么）；手机底部五个标签。

**几个体验细节**
- 建档是全屏一题一页，选完单选题自动下一题，球的颜色随你的选择实时变化。
- 灵感场景在对话里以深色卡片进行，每步一问，冥想有跟着呼吸缩放的圆圈。
- 每条回复下能看到「参考了哪些记忆」「做了什么」（收下好消息、加入计划……），对应 Muse 的 *You can't trust what you can't see*。
- 报告可以保存为图片（在浏览器本地生成，不上传）或复制文字。

## 4. 诚实的边界 · 决赛再做

- 检索是词法的，不懂同义改写（「早睡」和「十一点前上床」不一定能互相命中）。写入管线额外参考最近记忆来弥补去重，但检索本身要等接 embeddings 才能根治。
- 一次回复要两轮模型调用，gpt-6.1-sol 下常见 6–12 秒。
- 冥想是文字 + 呼吸动画，没有语音（会议待办：调研火山引擎语音 SDK 延迟）。
- 主动消息只在网页内出现，没有推送通知。
- 小光的球形外观受上游许可限制，只能用于非商业演示；正式产品要换成自有形象（表情引擎本身可以另行取得商业授权）。
- 没有找回密码、没有第三方登录。
