## 1. 创意：能做什么

### 1.1 产品愿景

**一句话**：小光是显化陪伴 agent——它只做一件事，把你「想成为的人」收成今天能走的一小步；它不是万能助理。

三个递进，也是答辩时的三条：
1. **比聊天机器人多一层状态**：它知道你今天有几件待做、宠物差多少经验、上周你选过「中断时先别提」。模型负责理解和表达，产品负责状态、记录和推进。
2. **比待办 App 少一层负担**：不要求你维护系统。聊天里说一句「今天主动提了个问题」，它问一句要不要记，就留下了。
3. **高光时刻是一个瞬间**：第 14 天，它把「室友记得你少糖」「第一次主动提问」这些你以为它忘了的小事串成一份报告，让你觉得「原来你都记得」。

**能力边界（写进系统提示，也写进产品）**：可以做目标拆解、习惯支持、情绪整理、一般生活建议、产品内记录与检索；
不自称治疗师、不包办现实行动、不凭空创造你的经历、不调用没接入的服务。用户问没接入的能力时，它说明暂不支持。

### 1.2 目标用户

主目标：**有具体愿望但容易中断，且不想被催的人**。学生的交换/表达焦虑、年轻职场人的作息与习惯，是这个人群最常见的两个入口。

判断依据不是「谁需要目标管理」（那太宽），而是：**谁最容易因为被评判而放弃**。
所以产品的核心动作不是「提高完成率」，而是**降低中断后的回归成本**——这也是「偷懒日不清零」和「中断时怎么陪你」两个设计存在的原因。

次目标：**不写日记但希望生活被看见的人**。好消息入口的低门槛（一句话、可来自聊天）就是为这群人做的。

不建议作为目标：需要专业心理干预、医疗或投资建议的人；强工具/代码代理需求。这两类会被明确转介，而不是硬接。

### 1.3 核心功能：八个模块，但只有一个主入口

八个模块按「用户此刻想干什么」分成三组，而不是八个同权重的标签页（Muse 的教训）：

| 组 | 模块 | 用户拿到什么 | 实现状态 |
|---|---|---|---|
| 陪你 | 小光对话 | 唯一的入口与人格主体 | 已实现，真流式 + 工具 |
| 陪你 | 蜕变计划 | 愿望 → 小步 → 完成/放一放 | 已实现，含小树园 |
| 陪你 | 好消息 | 一句话留下小事；偷懒日不清零 | 已实现 |
| 养成的 | 成长进化 | XP 账本、形态、分支、徽章、图鉴 | 已实现，9 张图 |
| 探索 | 点子 | 点一下就进入可玩场景（6 个） | 已实现，全部为真状态机 |
| 探索 | 心灵学堂 | 团队内容，可读、可让小光解释 | 已实现，8 篇 |
| 探索 | 蜕变报告 | 14/30 天，故事节点可核对 | 已实现 |
| 探索 | 我的空间 | 档案、记忆纠错、时间线、隐私 | 已实现 |

**为什么「重新认识我」不放在设置里**：它是一次 4 分钟的体验，不是一个配置项。放在「点子」里，用户会去玩；放在设置里，永远不会打开。它的产出（中断时的偏好）却会改变之后每一次对话——这是「体验入口」和「配置」的正确分工。

**显化的落地方式**：七步不做成一个仪式流程，而是化进对话和场景。澄清 → 「说清想要的」；信念 → 「我配得上它，因为……」；感受 → 短冥想；行动 → 5 分钟小步；感恩 → 三分钟感恩；释放 → 写下可放下的执念；见证 → 14/30 天报告。

### 1.4 与讨论稿的偏离（及原因）

| 讨论稿写的 | 这一版怎么做 | 为什么 |
|---|---|---|
| 首页 Agent 主区域 + 侧边栏放计划/好消息/成长/我的空间 | 同左，但**右栏「此刻」常驻宠物 + 今日小步 + 待确认猜测** | 用户不需要点进成长页就知道「我离下一形态多远」，这是留存动机 |
| 八个模块都要能找到 | 三组导航；移动端底栏 9 项横向滚动 | 八项平铺在小屏上会挤成两行小字（第一版实测如此，已修） |
| 14/30 天报告 | 保留，且**首屏就给出「当下回顾」** | 初赛评委看不到第 14 天；不能让核心功能在 demo 里不可见 |
| 宠物从细胞→蝌蚪→乌龟→山海经 | 种子→游星→雏龟→**化形（三选一）**→成年 | 三选一让「选择」成为演示时刻；分支比单向链条更能说清「你的选择留下痕迹」 |
| XP 每日 120、四类各 30（讨论数字） | 采用，并写成**账本 + 幂等键** | 这是讨论稿里唯一能被后端验证的规则，值得做实 |

## 2. 技术：怎么落地

### 2.1 Agent 架构

**一个主 Agent + 按需工具 + 确定性业务流程**，不引入多 Agent 编排（与会议一致）。

```
浏览器 (原生 ES 模块)
 ├ 对话 ── SSE ──▶ POST /api/chat ─▶ agent.chat()
 │                                    1 检索记忆 (FTS5 + 新近度)
 │                                    2 组装提示词：人设 + 核心档案 + 互动偏好 + 检索结果 + 成长规则
 │                                    3 流式调用模型，带 10 个工具（≤4 轮）
 │                                    4 工具写库 → 真实回执 → 再回到模型
 ├ 成长 ──────── /api/growth*  ─▶ growth.py（账本、上限、去重、形态）
 ├ 学堂 ──────── /api/academy* ─▶ academy.py（只读）
 ├ 报告 ──────── /api/report    ─▶ 规则算事实与节点 → 模型只润色叙事
 └ 后台：记忆写入管线 + 主动消息调度线程
```

**分层原则**：模型只能「提议」，不能记账。
- 经验值只由 `growth.award()` 写入，模型通过工具触发，拿到的永远是真实回执；
- 报告中「这段时间有几个小步」这类事实由 SQL 算，模型只负责把这些事实写成一段话；
- 学堂内容只有读函数，服务端**没有任何**写文章、改文章的接口。

### 2.2 模型选择

当前配置：ModelFlare 的 `gpt-6.1-sol`（OpenAI 兼容，`reasoning_effort=low`），密钥只在服务端 `.env`。
选择依据不是参数，而是四件能被测出来的事：中文语气的稳定性、工具调用正确率、首字延迟、单轮成本。

本版实测（本机，2026-10-27）：

| 场景 | 结果 |
|---|---|
| 「帮我记住我喜欢吃寿司」 | 正确调用 `remember`，写入 `kind=preference`，回复 12 字，卡片显示「已写入」 |
| 「我三天没健身了」 | **不**调用任何写入工具；回复遵循用户偏好（「先不把它变成对自己的评价」），未贴人格标签 |
| 「水桶效应是什么意思」 | 调用 `knowledge_search`；命中后引用学堂来源；未命中时明确说「学堂里没有」 |
| 「我什么时候能进化到下一阶段」 | 调用 `get_growth`，回答 306 XP / 差 54 / 三个分支名，与数据库一致 |
| 报告生成 | 规则节点即时返回；模型润色约 6–8 秒，前端先渲染再用润色版替换 |

**降级**：模型不可用时，聊天给出「我这边连不上了」，报告退回模板文案，计划/好消息/学堂/成长等非 AI 页面完全可用。

### 2.3 长期记忆

四类分开存，这是本产品最重要的技术约束：

| 类型 | 存在哪 | 写入时机 | 能否被模型改 |
|---|---|---|---|
| 核心画像（称呼、愿景、偏好、边界） | `profile` 表 | 建档 / 我的空间 / 明确偏好工具 | 只能通过工具改字段，不能改别的 |
| 用户明确要求记住的事实 | `memory` (status=active, source=chat:explicit / confirmed) | 说「帮我记住」时即时写入 | 可 ADD/UPDATE，可被用户删 |
| 模型推测 | `memory` (status=guess) | 每轮对话后异步抽取，**每轮最多 1 条** | 不能当事实用，**必须用户点「对」才转正** |
| 业务数据（步骤、好消息、经验、场景） | 各自的表 | 工具 / 页面操作 | 模型只能经由工具，规则在后端 |

**检索**：SQLite FTS5，中文按二元组切分，再乘新近度衰减和记忆类型权重（边界 > 愿景 > 偏好 > 事件）。
没有上向量库——在「几十到几百条短个人事实」这个规模上，词法检索的可解释性更高，且能解释「为什么召回了这条」。

**关键规则：事件 ≠ 人格**。系统提示明确写了：三天没健身是带日期的事实，最多记成事件；人格判断只能来自用户自己说的，或反复出现后被用户确认。

**用户掌控**：「我的空间」可查看、编辑、删除任意记忆；删除是真删（含检索索引）；未确认的猜测单独一栏。

### 2.4 工具调用

| 工具 | 权限 | 写不写 | 失败时 |
|---|---|---|---|
| `search_memory` | 读 | 否 | 返回空列表 |
| `remember` | 写 | 是 | `ok:false`，模型必须说没写成 |
| `add_step` / `complete_step` | 写 | 是 | 「没找到这一步」，不加经验 |
| `log_good_news` / `log_lazy_day` | 写 | 是 | 如实返回 |
| `get_growth` | 读 | 否 | 读真实账本 |
| `knowledge_search` | **只读** | 否 | 没命中就说没命中，不许自己编 |
| `set_care_style` | 写偏好 | 是 | 枚举校验，非法值拒绝 |
| `start_scene` | 写场景 | 是 | 场景不存在则拒绝 |

**回执与幂等**：完成步骤的经验以 `step:<id>` 为引用，同一步重复完成不会重复加分；好消息同理。
这条规则在 demo 里可验证：连续点两次同一个勾，第二次返回「这件事已经计过分了」，经验不变。

### 2.5 技术评估

可验证的指标（都能用 `demo/tests` 里的假模型 + 真服务器测）：

| 指标 | 本版现状 | 怎么测 |
|---|---|---|
| 数据隔离 | 22 个端到端测试通过，含「A 的好消息不出现在 B 的 bootstrap」 | `python -m unittest discover -s demo/tests` |
| 写入真实性 | 工具失败不增加经验、不显示「已记住」 | 测试覆盖 + 手动 |
| 经验上限/去重 | 按 (source, ref) 幂等；每类 30、每日 120 | 演示账号账本可逐条核对 |
| 报告可追溯 | 每个故事节点带 `sources`，前端可展开 | 报告页「核对来源」 |
| 首字延迟 | 未做 p95 统计（诚实标注） | 需加日志聚合 |
| 记忆命中率 | 未做真实用户评测（诚实标注） | 需 5–10 人种子测试 |

**已知弱点**：
- 中文词法检索对同义改写不敏感（「十二点前睡」vs「一点才睡」），当前靠「最近 8 条记忆」补召回；
- 主动消息依赖线程轮询，不是真正的定时任务队列；
- 没有速率限制之外的成本控制，长对话会推高 token。

### 2.6 产品落地

**当前形态**：单机 Python 标准库 + 每用户一个 SQLite + systemd + Caddy，`bash deploy/deploy.sh` 一条命令上线，带备份与回滚。
这个形态的优点是答辩时可以当场打开数据库验证「没有假数据」；缺点是横向扩展需要换存储层。

**P0（已达成）**：主 Agent、计划、好消息、经验、首页、真实落库、数据隔离、错误不谎称成功。
**P1（部分达成）**：主动消息（有）、点子场景（有）、学堂检索（有）、14 天回顾（有）、日终记忆整理（**未做**，现在是每轮异步抽取）。
**P2（未做）**：30 天精致报告模板、宠物图鉴历史、移动端 App、语音。

## 3. UI：用户体验

### 3.1 页面设计

**三栏桌面壳**：左轨（236px，分组导航 + 宠物摘要 + 账号）/ 中央画布（对话或页面，最大 780px 阅读宽度）/ 右栏「此刻」（312px，宠物、今日小步、待确认猜测、快捷入口）。

为什么是这三块：Muse 的「Agent 主视图 + 其他入口」是对的，但它把太多东西塞进侧栏；我们的取舍是**右栏只放「和今天有关」的东西**——宠物、今天的小步、等你点头的猜测。计划的历史、学堂的书、报告的故事，都在中央画布展开。

**对话是主工作台**：不分会话，按日期分隔，整段历史是一条线。工具结果不写成一句话，而是落成结构化卡片（计划卡 / 好消息卡 / 记忆卡 / 成长卡 / 学堂卡），卡片里带真实回执和经验变化。
记忆检索在回复下方以一条可展开的细线呈现（「小光参考了 3 条记忆」），点开能看到是哪三条、哪条是猜测。

**首登**：一屏一题，可以跳过任意可选题，也可以在第一步就「先跳过，直接聊」。判断题优先给选项，不给空白输入框。

### 3.2 美术风格

**一句话**：暖纸底、墨色字、单一青玉色。层级靠字号、字重和细线，不靠一层层卡片和阴影。

- 底色 `#faf7f1`（纸），文字 `#1a1814`（墨），唯一的品牌色 `#2f6b58`（青玉），金色 `#a87c38` 只用于「好消息 / 经验 / 等待确认」。
- 标题用衬线（Noto Serif SC），正文用无衬线；标题承担情绪，正文承担信息。
- 全站几乎没有阴影，只有输入框和弹层有；分隔用 1px 半透明细线。
- 背景有一层极淡的网点，模拟纸面；暮色主题把纸色换成深墨，网点换成微光。
- 动效克制：消息上浮 6px、宠物图缓慢呼吸、光球按状态改变节奏；`prefers-reduced-motion` 全关。

**为什么不做插画风**：显化本身就是「留白 + 可能性」，画满的界面会把用户的想象挤掉。宠物是唯一的具象物，其余都用排版。

### 3.3 Agent 形象

**两只角色，明确分开**（这是讨论稿里最重要的一条，我们完整执行了）：

1. **小光**：一枚自绘 SVG 光球，青玉渐变、两点眼睛、一条微笑弧，三种状态（静息/思考/回应）只是呼吸节奏和眼睛开合不同。
   - 原创，无第三方授权问题（上一版的 emotion-ball 仅限非商业使用，已移除）。
   - 不随等级变化——这是刻意的：小光是稳定的人，不是会变形的宠物。
2. **小芽（宠物）**：独立的养成对象，gouache 绘本风，暖纸底、青玉与金色，9 张生成图：
   种子 → 游星（蝌蚪）→ 雏龟 → 三选一（青龙 / 九尾 / 白泽，各有幼年与成年）。

生成方式：`tools/gen_pets.py`，调用 `gpt-image-2`，统一风格提示词，输出后压缩为 620px WebP（每张 16–63KB）。

### 3.4 功能分区

```
左轨                     中央画布                        右栏「此刻」
├ 陪你                  对话（主工作台）                 ├ 宠物 + 一句状态
│  ├ 对话               ├ 开场 / 历史 / 日期分隔          ├ 小光留了话（站内主动消息）
│  ├ 蜕变计划           ├ 工具结果卡（不是一句话）        ├ 今天的小步（可直接勾）
│  └ 好消息             ├ 记忆溯源（可展开）              ├ 等你确认的猜测
├ 养成的               ├ 输入框（星星=好消息 / 月亮=偷懒） └ 快捷（好事/偷懒/重新认识我）
│  └ 成长进化          蜕变计划：愿望 → 小树园 → 待做 → 已完成
├ 探索                成长：宠物大图 → 经验 → 四类上限条 → 形态路线 → 分支 → 徽章 → 账本
│  ├ 点子              点子：分组卡片（默契/愿望/日常），点一下进对话
│  ├ 心灵学堂          学堂：按章节分组；文章页有摘要、正文、来源、练习
│  ├ 蜕变报告          报告：封面 → 信 → 故事节点（可核对）→ 惊喜 → 分享预览
│  └ 我的空间          空间：档案 / 记忆（含猜测）/ 时间线 / 隐私 / 导出
```

**点子与学堂必须长得不一样**：点子是「点一下，小光带你做」（青玉图标 + 时长 + 进入对话）；学堂是「读团队审核的内容」（金色图标 + 章节 + 阅读）。两者共用卡片网格，但图标色、右上角标签、行动文案都不同。

**移动端**：不重做一套，而是同一信息架构的收窄——左轨变底部横条（可横滑），右栏变抽屉，中央画布变单栏，字号与点击区放大。

## 4. 没做到 / 不知道的（诚实清单）

1. **日终记忆整理未实现**：现在是每轮对话后异步抽取（mem0 式 ADD/UPDATE/DELETE），不是「每天汇总一次」。对话量大时会多花 token。
2. **主动消息不是真定时队列**：10 分钟轮询一次，且只做站内消息，没有手机推送（讨论稿也不要求第一版做）。
3. **记忆检索没有向量层**：中文同义改写召回弱；未做真实用户命中率评测。
4. **延迟与成本没有 p95 数据**：只有单次实测，没有统计。
5. **宠物的「图鉴 / 历史形态」没做**：选完分支后看不到走过的形态记录。
6. **30 天报告**：逻辑贯通，但没有专门的 30 天视觉模板（与 14 天共用）。
7. **分享**：只做「复制文字版」，没有导出图片（上一版有 html2canvas，这一版为了减小依赖去掉了）。
8. **语音、移动 App、生图定制宠物**：未做，且不在初赛范围。
9. **模型对比**：只测了当前生产模型，没有做候选模型盲测。
