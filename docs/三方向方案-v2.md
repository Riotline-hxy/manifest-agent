## 1. 创意：能做什么

### 1.1 产品愿景

**一句话**：小光是显化陪伴 agent——只帮你把「想成为的人」收成今天能走的一小步；不是万能助理。

答辩时可以用三层递进说清楚：

1. **比聊天机器人多一层状态**：它知道你今天有几件待做、宠物离分化还差 4 经验、你选过「中断时陪我找原因」。模型负责理解和表达，产品负责状态、记录和推进。
2. **比待办 App 少一层负担**：不需要维护系统。聊天里说一句「被老师夸了」，就落成好消息；夜里它再把当天值得留下的整理一遍。
3. **高光时刻是一个瞬间**：第 14 天，「播放回顾」把你以为它忘了的小事一页一页放出来——「原来你都记得」。

**能力边界**（写进系统提示，也写进产品）：可以目标拆解、习惯支持、情绪整理、一般生活建议、产品内记录与检索；不自称治疗师，不包办现实行动，不编造你的经历，不调用没接入的服务。

### 1.2 目标用户

主目标：**有具体愿望、但容易中断，并且一被评判就想放弃的人。** 学生的表达焦虑、年轻职场人的作息和健身，是最常见的两个入口。

核心动作因此不是「提高完成率」，而是**降低中断以后回来的成本**：偷懒日不清零、中断时按你选的方式回应、「先放一放」不算失败。

次目标：**不写日记、但希望生活被看见的人**——好消息星空和夜里整理是为他们做的。
第三类：**喜欢养成和收集的人**——宠物分化和全功能徽章是为他们做的，但它们只记录真实行为，不鼓励刷分。

### 1.3 核心功能：八个模块，一个入口

八个模块分三组排布，不做八个同权重标签：

| 组 | 模块 | 用户拿到什么 |
|---|---|---|
| 陪你 | 对话 | 唯一的人格主体；工具结果落成带贴纸的卡片 |
| 陪你 | 蜕变计划 | 愿望 → 小步；每完成一步，浮岛上长出一株植物 |
| 陪你 | 好消息 | 每条好消息是夜空里的一颗星，点开能看到那天发生了什么 |
| 陪你 | 成长进化 | 宠物舞台、进化图、亲和度、27 枚徽章、经验账本 |
| 探索 | 点子 | 6 个可玩场景，点一下进入「一课」 |
| 探索 | 心灵学堂 | 8 篇团队内容，书封卡片；小光只读、只解释 |
| 探索 | 蜕变报告 | 14 / 30 天；全屏故事模式 + 可核对来源 + 分享预览 |
| 探索 | 我的空间 | 档案、记忆（含修订记录）、夜里整理、时间线、设置 |

**主动关怀**是横向机制：站内消息出现在右侧「小窝」和对话线程里，23:00–08:00 不打扰，频率可调。

### 1.4 成长系统（重新设计）

**宠物线**（独立于小光，不随等级改变小光的样子）：

```
光蛋 ──(100)── 团子 ──(310 · 分化)──┬── 小焰 ──(650)── 焰尾狐   行动最多
                                   ├── 花苞 ────────── 花角鹿   好消息最多
                                   ├── 云朵 ────────── 云鲸     练习最多
                                   └── ？？？ ──────── ？？？   三样都不偏科（隐藏形态）
```

- **分化不是手选的，是你做出来的**：310 经验那一刻，看行动 / 好消息 / 练习三类累计经验的比例。之前一直能看到「它在往哪边长」的亲和度条，想换方向，就多做另一类事。
- **一眼看得清**：进化图把整条路线摊开；走过的节点点亮，正在偏向的分支用流动虚线和「可能是它」标出，其余是剪影，隐藏形态只有问号。路线清楚，结果保留悬念。
- **数字规则**沿用讨论稿：行动 +10、好消息 +6、练习 +12、每天第一次来聊 +8；每类每天 30、总共 120；按「来源 + 引用」去重，同一件事永远只计一次；每 40 经验升一级。
- **今日任务**就是这四类来源：四件都做到，宝箱打开（纯庆祝，不额外加经验，守住 120 上限）。

**徽章**（27 枚，9 类）：

| 类 | 例子 |
|---|---|
| 对话 | 第一句话 · 话匣子（30 句） |
| 计划 | 第一步 · 七次落地 · 习惯成形（30 步） |
| 好消息 | 第一颗星 · 收集星星（10）· 星罐满了（30） |
| 练习 | 静下来 · 练习者（5 次）· 重新认识 · 都试过了（4 种场景） |
| 记忆 | 记住我（第一次让它记住）· 说清楚（确认 / 否定 / 修改一条记忆）· 被好好整理（第一次夜里整理） |
| 学堂 | 开卷 · 求知（5 篇） |
| 报告 | 回头看（打开一次报告） |
| 陪伴 | 休息也算（第一次偷懒日）· 回来了（休息之后又完成一步）· 一周 · 半个月 · 一个月 |
| 成长 | 破壳 · 分化 · 长大了 · 隐藏形态（未获得前名字是问号） |

「休息也算」「回来了」是刻意放进去的：中断本身也被看见，而不是只奖励连续。

### 1.5 与讨论稿的偏离（及原因）

| 讨论稿 | 这一版 | 原因 |
|---|---|---|
| 宠物从细胞→蝌蚪→乌龟→山海经 | 光蛋→团子→四分支→成年 | 按反馈去掉山海经；分支由行为决定，比单向链条更能说清「你的选择留下痕迹」 |
| 建档 8 题含「选一个它的气质」 | 去掉这一题，换成「中断时希望我怎么做」 | 小光形象固定（v0.3 共识），选气质已没有意义；中断偏好则贯穿整个产品 |
| 「现在小光有多了解我」做成展示页 | 直接交给真实对话 | 让模型基于真实记忆说出「记得的」和「不确定的」，比静态列表更像讨论稿描述的体验 |
| 14 / 30 天报告 | 保留，并加「播放回顾」故事模式；未满天数时也能看当下回顾 | 初赛评委看不到第 14 天，核心功能不能在 demo 里不可见 |

## 2. 技术：怎么落地

### 2.1 Agent 架构

一个主 Agent + 按需工具 + 确定性业务流程，不做多 Agent 编排。

```
浏览器（原生 ES 模块，无构建步骤）
 ├ 对话 ── SSE ──▶ /api/chat ─▶ agent.chat()
 │                               1 每天第一句 → 签到经验（幂等）
 │                               2 检索记忆（FTS5 二元组 + 新近度 + 类型权重）
 │                               3 系统提示 = 人设 + 核心档案 + 中断偏好 + 检索结果 + 成长规则
 │                               4 流式调用模型，带 11 个工具（≤4 轮），每个工具返回真实回执
 │                               5 表情事件（mood）→ 前端 Emotion Ball
 ├ 成长 ─────── growth.py：账本 / 上限 / 去重 / 分化 / 徽章 / 一次性庆祝标记
 ├ 学堂 ─────── academy.py：只读
 ├ 报告 ─────── 规则算事实与节点 → 模型只润色那封信
 └ 后台线程（每 10 分钟）
      ├ 03:00 后：为每个用户整理「昨天」（digest.py）
      └ 主动消息：空闲 ≥ N 小时、静默时段不发、一次最多一条未读
```

**原则：模型只能提议，不能记账。** 经验只由 `growth.award()` 写；报告里的数字由 SQL 算；学堂只有读函数；庆祝动画只在后端给出一次性标记（`evolved` / `badges_new`）时出现，前端不自己「演」。

### 2.2 模型选择

主对话：ModelFlare `gpt-6.1-sol`（OpenAI 兼容，`reasoning_effort=low`），密钥只在服务器 `.env`。
美术素材：openlux `gpt-image-1.5`（原生透明背景）。实测 `gpt-image-2` 在这个中转上返回 RGB 加假棋盘格，无法叠层；`flux-1.1-pro` 当时 503。

本版用真实模型跑了讨论稿的关键场景（本机，2026-10-27）：

| 用户说 | 实际行为 |
|---|---|
| 帮我记住我喜欢吃寿司 | 调 `remember`，立即写入受保护记忆 |
| 我三天没健身了 | 不写任何记忆；回复「也不等于你没毅力。你愿意和我一起看看，这几天是哪里卡住了吗？」（照「一起找原因」偏好） |
| 其实我现在不喜欢寿司了 | 调 `correct_memory`：旧文本、新文本、用户原话一起存进修订记录 |
| （夜里整理） | 新增事件「10月27日：连续三天没健身」——带日期的事件，没有性格标签 |
| 我什么时候能进化 | 调 `get_growth`，回答 306 / 差 4 / 分化规则，与数据库一致 |
| 水桶效应是什么意思 | 调 `knowledge_search`，只引用学堂文章 |

**一个被实测抓到的问题**：第一次运行时模型对「我三天没健身了」也调了 `remember`。提示词约束不够可靠，所以加了**服务端硬约束**：用户这句话里没有「记住 / 别忘 / 记一下」这类明确请求时，`remember` 直接拒绝，近况交给夜里整理。有测试覆盖。

**降级**：模型不可用时，聊天说「连不上了」，报告用模板信，夜里整理只写模板小结、不动任何记忆；计划、好消息、学堂、成长全部照常可用。

### 2.3 长期记忆

| 类型 | 存哪 | 何时写 | 谁能改 |
|---|---|---|---|
| 核心画像 | `profile` | 建档 / 我的空间 / 偏好工具 | 字段级，用户可改 |
| 明确记忆（受保护） | `memory`，source = `chat:explicit` / `confirmed` / `onboarding` | 「帮我记住」时立即写 | 用户；或用户当天原话里能逐字找到依据的整理 |
| 推测 | `memory`，status = `guess` | 夜里整理，每天最多 1 条 | 不用于理解用户，直到用户点「对」 |
| 事件与新发现 | `memory`，source = `digest` | 夜里整理 | 整理可更新 |
| 业务数据 | 步骤 / 好消息 / 经验 / 场景 / 徽章各自的表 | 工具或页面操作 | 只经由后端规则 |

**夜里整理**（`core/digest.py`）：

1. 取这一天的对话、好消息、完成的小步、练习；超过 1200 字的粘贴文本标成「长文资料」，不当作用户的经历。
2. 模型只输出**增量**（ADD / UPDATE / DELETE），不重写整份画像。
3. 改动受保护记忆时，必须给出用户当天的原话；**后端逐字核对**，对不上就拒绝，拒绝也会记下来。
4. 推测最多 1 条，以待确认状态进入。
5. 每次改动都写一条修订记录（旧文本、新文本、原因、依据），「我的空间 → 记忆 → 修订记录」可以看到。
6. 写一条当天小结和最多 3 个瞬间，「夜里整理」页按天展示。

调度：后台线程每 10 分钟检查一次，03:00 之后为「昨天」整理，每人每天一次。演示时可以在「夜里整理」页点「现在整理一下今天」。

**检索**仍是 SQLite FTS5（中文二元组）× 新近度衰减 × 类型权重，没有向量层（见第 4 节）。

### 2.4 工具调用

| 工具 | 读 / 写 | 约束 |
|---|---|---|
| `search_memory` | 读 | — |
| `remember` | 写（受保护） | **用户必须明确要求**，否则服务端拒绝 |
| `correct_memory` | 改 / 删 | 必须附用户原话，写修订记录 |
| `add_step` / `complete_step` | 写 | 完成按 `step:<id>` 计分，幂等 |
| `log_good_news` / `log_lazy_day` | 写 | 好消息按 `rec:<id>` 计分 |
| `get_growth` | 读 | 读取时不消费庆祝标记，留给界面 |
| `knowledge_search` | **只读** | 没命中就说没命中 |
| `set_care_style` | 写偏好 | 枚举校验 |
| `start_scene` | 写 | 前端随即打开「一课」 |

### 2.5 技术评估

| 指标 | 现状 | 怎么验证 |
|---|---|---|
| 测试 | 28 个端到端测试全部通过（真服务器 + 脚本化假模型） | `python -m unittest discover -s demo/tests` |
| 数据隔离 | 每用户一个 SQLite 文件；身份只来自 HttpOnly 会话 | 测试：A 的好消息不出现在 B 的任何接口 |
| 经验规则 | 每类 30 / 每日 120 / 去重 | 测试：连续完成 5 步得 10,10,10,0,0 |
| 分化与庆祝 | 按亲和度分化；进化和徽章各只报一次 | 测试覆盖 |
| 受保护记忆 | 没有原话依据就拒绝修改 | 测试：伪造的 UPDATE / DELETE 被拒 3 条 |
| 首字延迟 / 成本 | **未做统计** | 需要日志聚合 |
| 记忆命中率 | **未做真实用户评测** | 需要 5–10 名种子用户 |

### 2.6 产品落地

- 部署：单机 Python 标准库 + 每用户 SQLite + systemd + Caddy；`bash deploy/deploy.sh` 一条命令打包、备份、替换、重启、自检，并给出回滚命令。
- 前端零构建：原生 ES 模块，Emotion Ball 以普通脚本加载。
- 字体：源流圆体 CN（SIL OFL）按 Unicode 区段切成 14 片，按字频排序，页面只下载用到的片；拉丁字母和数字用 Nunito。共 2.6 MB，但单页通常只取 1–3 片（约 180–350 KB）。脚本：`tools/build_fonts.py`。
- 素材：28 张 WebP（共 1.1 MB），`tools/gen_assets.py` 一条命令重新生成。

## 3. UI：用户体验

### 3.1 视觉系统「森林夜」

参考 Forest 的层次感、多邻国的趣味性：

- **背景是一个场景，不是一块颜色**：深绿渐变 + 4 道缓慢摆动的斜射光 + 26 粒向上漂的光尘 + 闪烁的四角星 + 底部暗色远山。
- **字体圆润**：中文源流圆体（500 / 700），拉丁字母和数字 Nunito；大数字一律用粗圆数字，并且会滚动。
- **两种主色**：叶绿（完成、正确）和灯黄（经验、强调、主按钮）；粉 / 天蓝 / 紫只给分类和宠物分支用。
- **按钮可以「按下去」**：底部 4px 厚边，按下时整块下沉（多邻国式），主按钮带一道扫过的光泽。
- **贴纸体系**：28 张同风格 3D 贴纸（导航图标、工具卡片、任务、徽章、空状态、toast 都用它），统一了「有贴图但不杂乱」的观感。

### 3.2 动效清单（都有含义，不是装饰）

| 动效 | 何时出现 |
|---|---|
| 小光换表情 / 转圈 / 跳 | 对话中的每个状态：思考、翻记忆、检索、回答、完成、出错 |
| 工具卡片弹入、贴纸旋入 | 小光真的写了东西 |
| 「+10 XP」飞进顶栏，数字滚动 | 后端真的记了经验 |
| 彩纸 | 完成一步、收下好消息、完成练习 |
| 植物从浮岛里长出来 | 完成一小步 |
| 星星从夜空里亮起 | 收下一条好消息 |
| 全屏进化（旧形态抖动 → 闪白 → 新形态弹出） | 跨过 100 / 310 / 650 |
| 徽章翻转入场 | 获得新徽章 |
| 宝箱摇晃后打开 | 今日四件任务都完成 |
| 故事模式翻页 | 播放蜕变回顾 |

所有动效在系统「减少动态效果」设置下自动关闭。

### 3.3 Agent 形象

- **小光 = Emotion Ball**（灯黄色 blob）。对话页顶部常驻，名字下有一行实时状态（「在听你说」「在翻我们的回忆」「正在回你」「写好了」）；眼睛跟着鼠标；点它会跳一下并换一个好心情；看不见时暂停动画。
- **授权**：Emotion Ball 的引擎非商业免费，**球形角色外观永不商用**。本 demo 用于竞赛展示，页面底部有署名；正式商用前必须换成自研形象（适配层 `public/js/ball.js` 已把接口隔离好，换形象只改这一个文件）。
- **宠物与小光分开**：成长只发生在宠物身上，小光的样子不变。

### 3.4 功能分区与关键页面

```
左侧导航（贴纸图标）      中间主区                                右侧「小窝」
陪你                    对话：小光状态栏 / 线程 / 工具卡 / 输入框     宠物舞台 + 到下一形态的进度
 · 对话                 计划：愿望卡 + 浮岛花园 + 小步卡片           今日任务（四类）+ 宝箱

 · 好消息                成长：宠物舞台 / 进化图 / 亲和度 / 徽章 / 账本  小光猜的，对吗？
 · 成长进化              点子：今日推荐 + 便当盒分组卡               昨晚整理了什么
探索                    学堂：书封卡片；文章用浅色纸张卡片
 · 点子                 报告：封面数字 + 信 + 节点（可核对）+ 故事模式

 · 我的空间              顶栏：陪伴天数 · 今日经验 /120 · 等级环（悬停有解释）
```

**「一课」**（建档和全部引导场景共用，多邻国式）：上方粗进度条；小光 + 气泡提问；选项是带数字键和贴纸的卡片（键盘 1–9 可选，回车继续）；每答一题底栏变绿、小光开心一下；结束页显示经验滚动和「写回了什么」。

**移动端**：同一套信息架构收窄——导航变成底部横条，右侧小窝变成抽屉，顶栏只留经验和等级。

### 3.5 与讨论稿的偏离

| 讨论稿 | 这一版 | 原因 |
|---|---|---|
| 侧栏放所有功能入口 | 侧栏按「陪你 / 探索」两组；右侧栏只放和「今天」有关的东西 | 右侧栏常驻宠物和任务，回访动机最强 |
| 点子与学堂样式要区分 | 点子 = 彩色便当卡 + 「开始」；学堂 = 书封 + 「阅读」 | 一个是做，一个是读 |
| 报告不是长文本 | 页面上是信 + 节点；另有全屏故事模式 | 惊喜感来自节奏，不只来自文字 |

## 4. 没做到 / 不知道的（诚实清单）

1. **记忆检索没有向量层**：中文同义改写召回弱，没有做真实用户的命中率评测。
2. **主动消息与夜里整理靠 10 分钟轮询**，不是真正的任务队列；只做站内消息，没有手机推送（第一版本来也不要求）。
3. **延迟与成本没有 p95 统计**，只有单次实测。
4. **宠物图鉴只记录当前路线**：选定分支后，看不到「如果当初偏向另一边会是什么」，也还没有图鉴收集。
5. **30 天报告**和 14 天共用版式，没有单独的视觉模板。
6. **分享只到「复制文字版」**，还不能导出图片卡。
7. **Emotion Ball 不能商用**：正式产品前必须换成自研形象（只需改 `ball.js`）。
8. **字体总量 2.6 MB**：按需加载后单页通常 1–3 片，但首次访问在慢网络下仍需要几百 KB。
9. 语音、移动 App、AI 生成的定制宠物：未做，也不在初赛范围。

## 5. 答辩演示顺序（约 8 分钟）

1. 打开线上 → 「先体验一下」：入口页上小光换着表情说话。
2. 对话：说「帮我记住我喜欢吃寿司」→ 记忆卡片；再说「我三天没健身了」→ 不贴标签、按偏好陪你找原因；再说「其实我现在不喜欢寿司了」→ 更正卡片。
3. 我的空间 → 记忆 → 修订记录：能看到旧说法、新说法和用户原话。
4. 我的空间 → 夜里整理 → 「现在整理一下今天」：三天没健身被记成带日期的事件。
5. 成长进化：306 经验、差 4 分化、进化图上正在偏向焰尾狐。
6. 蜕变计划：勾掉一个小步 → 植物从岛上长出来 → 经验飞进顶栏 → **全屏进化成「小焰」** → 新徽章「分化」。
7. 点子 → 今日推荐 → 「一课」全屏问答 → 完成页。
8. 蜕变报告 → 「播放回顾」故事模式 → 分享预览只公开你勾的内容。
9. 最后用两个浏览器登录两个账号，证明数据互不可见。
