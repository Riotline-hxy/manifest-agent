## 0. 这一版回应了什么

**第六轮（v2.6）：小光更像朋友，会定时、记得更久；侧栏更少；手机版重做。**

| 反馈 | 这一版的做法 |
|---|---|
| 新用户的题目里出现 `function sub() { [native code] }` | 选项是字符串时，读 `o.sub` 会拿到 JS 自带的 `String.prototype.sub` 函数并被打印出来。选项统一转成对象，渲染时只认字符串的副标题 |
| 「留下一个瞬间」只有三个预设问题 | 问题提示变成可选（「也可以直接写」），每个愿望可以加最多 6 个自己的问题（带 × 删除，存在愿望上）；心情也能自己加词（存在画像上） |
| agent 没有定时任务，像在引导用法的人机 | 新增**例行任务**：对小光说「5 分钟后提醒我开会」「每天早上给我一句鼓励」就会真的安排上（`schedule_task`）；小光面板「今天」里像 Grok 一样列出所有例行任务，每个都有开关，可以新建、编辑、删除；夜里整理、主动找你聊、鼓励语也作为内置例行任务列在里面。到点后消息出现在对话里（带「例行任务」标签），网页开着时 30 秒内弹出提示和浏览器通知 |
| 对话记忆太短（只记得十几条） | 最近 **3 天的对话原样**放进上下文（上限 2.4 万字，至少 16 轮）；更早的靠三层：每天的小结、小光每晚更新的**笔记本**（用户可在「我的空间 → 夜里整理」查看和修改）、以及可以翻全部旧聊天的 `search_chats`。成本分析见 2.7 |
| 侧栏入口太多 | 侧栏只留 6 个页面：对话、蜕变计划、好消息、成长进化、点子、心灵学堂。蜕变报告从蜕变计划右上角进入。左下角头像只有一个入口，点一下进入「我的空间」，记忆 / 夜里整理（含笔记本）/ 时间线 / 设置都在里面（2.6.1 去掉了头像弹出菜单和手机抽屉里的额外分区） |
| 终点的火柴人粗糙 | 「理想身材与健康」的愿景换成线描的心形 + 心跳线，和其他愿景同一种笔触 |
| 手机上体验不好 | 参考 Muse：左上角圆形菜单按钮打开侧滑抽屉，里面只有 6 个页面，底部一个「我的空间」入口；底部横条只留 5 个主入口；大屏不变 |
| 用户名称没办法修改（2.6.1） | 「我的空间」名字旁的铅笔、或「设置 → 名字」：改称呼（小光怎么叫你、页面显示的名字）；正式账号还能改登录用户名（重名会提示），体验账号注册后才有用户名 |
| 回复没有人味、像 AI | 人设改成「先是朋友，然后才是陪练」：先回应人再回应事，说出 TA 的情绪，有自己的反应，自然提起聊过的事；禁止「我理解你的感受」「作为一个 AI」「你可以尝试以下方法」「我不能……但你可以……」等说法。新增三种**性格**：温柔 / 有条理 / 活泼，建档时选（第 8 题），设置里随时换 |

线上用真实模型复测：「你能 5 分钟后提醒我开一个会议吗」→「好，给你安排好了，01:06 提醒你开『财富与爱情会议』✨」（活泼）；1 分钟的提醒在 80–90 秒内出现在对话里；「被导师当众批评，好难受」→「被当着大家的面批评，真的很刺心啊……要不要跟我说说，导师批评了什么？」；「还记得我上周说过 Mia 的什么事吗」→ 用 `search_chats` 找到并复述，找不到时会直说「可能记漏了」。复测中发现并修掉：示例账号「今天 22:00」的种子消息在晚上 10 点前会排到最新，导致回复气泡显示成旧消息；以及活泼性格在用户难过时自作主张开了偷懒日（现在只在用户明确要休息时才开）。

**2.6.2 的补充**

| 反馈 | 做法 |
|---|---|
| 右侧面板文字太多；夜里整理、主动问候、鼓励语不该算「例行任务」 | 例行任务只列用户自己让小光定的；空的时候只有一行「还没有，跟小光说一声就能定」。主动消息频率仍在设置里调，其余是底层机制，不再展示 |
| 「小光留了话」「夜里整理了」不要单独成卡，合进鼓励语 | 合并成一张「小光的一句话」，但**不随机**：按优先级显示最该看的一句——没读的留言 / 到点提醒 → 昨晚整理时注意到的一件事（只在两天内、且是模型写的才出现，模板小结不上首页）→ 最近的你 / 送你一句。右上角小圆点可以翻到另外几句，点留言进对话、点昨晚的那句进「夜里整理」。夜里整理的那句话改成小光第二天对你说的一句（≤40 字，带一点自己的感受，比如「面试官那一笑，我猜你心里松了一大口气吧」） |
| 动态要分区 | 按天分组（今天 / 昨天 / 日期），组内只写时间；建示例账号时顺手产生的「加了习惯」「定了里程碑」不再出现 |
| 计划周期太长 | 计划什么时候实现：14 天 / 30 天 / 90 天 / 自定义（点了才出现日期选择），新愿望默认 14 天，下面实时写「14 天后，11月13日」；建档自动生成的愿望默认 30 天 |

**2.9.2 的补充**

| 反馈 | 做法 |
|---|---|
| 蜕变报告入口位置不好，图标不居中 | 入口挪到蜕变计划页面最底部，做成一整行卡片；图标歪是因为样式 `.report-entry span` 把图标方块（也是 span）改成了竖排，现在只作用在文字上 |
| 手机对话页能左右滑 | 手机上小光那一列宽度设成 92%，再加上 34px 头像和 10px 间距，比一行宽了约 15px，整段对话就能被横着拖。改成 `calc(100% - 44px)`，对话区再禁止横向滚动 |
| 让小光改已经定好的里程碑，它说改不了 | 原因是小光只有「新增 / 提议 / 完成 / 打卡」的工具，没有「改」，只好重新提议，结果被去重拦下。新增 `edit_plan`：直接改里程碑（名字、日期、完成）、习惯（名字、频率、收起）、小步（名字、先放一放、删掉）和愿望本身（名字、计划日期、向往）；按 id 或名字找，名字被转述（「选定慵懒爵士曲目」↔「选定一首慵懒浪漫的爵士曲」）也能按两字片段的重合度认出来。线上复测：「那个『能用英语聊满 20 分钟』的里程碑有点远了」→ 小光问提前到哪天 →「你改一下吧」→ 直接改到 11 月 16 日 |

**2.11：小光能看见、能改动、会提醒（把各个功能串起来）**

线上反馈：让小光删掉愿望「早睡早起」，它问「要我帮你删掉吗？」，用户说「可以」，结果「没有要改的内容」。原因是 `edit_plan` 对愿望只支持改名字和日期，「删掉」被忽略了；而且名字对不上时会悄悄改到「正在看的那个」愿望上。借这次把小光在每个功能里的能力补齐：

| 能力 | 做法 |
|---|---|
| 查功能说明 | 新增 `app_guide`：每个页面在哪、能做什么、规则（经验上限、偷懒日暂停什么、习惯怎么按周算、通知怎么开），以及「页面上做不到、只能让小光做的」。一张简短的 App 地图直接放进系统提示 |
| 看用户的数据 | 新增 `look_up`，按功能读真实数据：计划全貌 / 某个愿望 / 习惯打卡（最近两周哪天、连续天数）/ 小步 / 瞬间 / 好消息 / 偷懒日 / 记忆 / 笔记本 / 夜里小结 / 例行任务 / 设置 / 动态日志 / 成长 / 报告数字 / 学堂 / 点子 / 要留意的事；每项带 id，改的时候能指准。核心档案里改成列出**所有**愿望的路径和收起的愿望 |
| 增删改用户写下的东西 | `edit_plan` 支持 add / change / remove / restore × 愿望、里程碑、习惯、小步、瞬间（愿望和习惯「删掉」是收起，能找回；收起愿望后它的习惯也不再参与打卡和提醒）；新增 `edit_good_news`（好消息页上改不了、删不掉的，小光能做）、`edit_task`（关掉 / 打开 / 删掉 / 改时间）、`update_settings`（称呼、小光的名字和性格、主动消息、互动偏好、宠物名、氛围、作息、边界）；`log_lazy_day` 可以撤销；`log_good_news` 能记内心戏。到达里程碑、在对话里留下瞬间照样计经验 |
| 需要用户同意 | 服务端把关：改动类工具只有在这句话里有改动的意思（删 / 改 / 加 / 收起 / 找回 / 推后 / 放一放……），或者是对小光上一句提问的简短同意（「可以」「好呀」）时才执行；只是聊天、倾诉（「最近好累啊」）时会被拦下，小光只能先问。「我到了 / 做完了」这种报告事实的不拦 |
| 主动提醒和引导 | 新增 `core/nudges.py`，从计划和记录里算出值得提的事：里程碑快到期 / 已过期、愿望的日子快到、每天的习惯今天还没打卡（傍晚后）、每周的习惯这周跟不上、连续打卡、小步放了一周以上、愿望还没有路径、两周没留下瞬间、昨天偷懒今天回来。聊天时放进每轮上下文（一次只提一件、难过时不提、偷懒日不提、选了「先不提」就不提）；主动消息和「到点让小光说点什么」的例行任务也优先用这些真实情况 |

顺手修的：对话流到一半连接断了，之前整轮回复会丢、不入库，现在已经写出的部分会保存；用户关掉网页时，服务端继续把这一轮跑完存下（之前注释写着会存，实际没存）；模型把 id 连方括号抄过来（`[r_2ac0bb9e3216]`）也能认出；卡片标题「改好了计划 · 没成功」改成按结果显示。

成本：工具定义从约 8.1k 字符增到 11.3k，人设加地图从 3.1k 增到 4.7k，每次请求多约 2–3k token。

**2.6.5：面板顶部的一句话只留两种**

讨论后决定：只保留「最近的你」和**对自己说**（第一人称的内心肯定语，风格参考 I am 类 App：「我值得拥有精彩的人生。」「事情会按照所需的方式得到解决。」）。每次打开小光面板随机显示一句，点一下换一句；「最近的你」大约四成概率出现，超过 3 天没更新就不再出现。肯定语共 28 句，8 句通用，其余按愿望类别（心灵平静 / 自信 / 身体 / 事业 / 关系 / 自由）只给有对应愿望的人。之前合进来的「小光留了话」「昨晚整理时」不再出现在这张卡上：留言在对话里（导航有红点），夜里整理在「我的空间 → 夜里整理」。名句库随之删除。

**2.6.3–2.6.4 的补充**

| 反馈 | 做法 |
|---|---|
| 「小光的一句话」要点一下就能切换 | 点整张卡片就换下一句（循环），小圆点只做提示；留言 / 昨晚那句下面单独有一个小链接「去回一句」「看看整理了什么」 |
| 小光说「知道了」却没记；用户说「那你加进去吧」被拦下；它还向用户解释「系统没识别」 | ① 记忆写入的判断看上下文：这一句明确要求（记住 / 记着 / 记下 / 加进 / 写进 / 笔记本 / 删掉 / 换成 / 改成……），或者是对上一句请求、对小光「要我帮你记下来吗？」的简短同意（整句就是「好呀」「对的」「可以」，「对了我养了只猫」不算）。② 新工具 `update_notebook`：往笔记本里加、改、删（加的同时记成一条记忆），笔记本在「我的空间 → 夜里整理」可见。③ 提示词：说「记住了 / 加进笔记本了」必须是这一轮真的调用了工具；没让记就问一句；不要向用户解释工具和系统。④ 一轮里被拦下的写入工具不再给模型重试，避免把几次尝试拼成一段乱回复 |

线上真实模型复测（同一段对话）：「帮我加一个『我爱看动漫』吧」→ 加进笔记本；「对了我养了一只叫团团的猫……」→ 只聊猫，不乱记；「我其实特别怕打雷，你能记着点吗」→ 记住；「那条动漫的你删了吧，我想换成：我爱看宫崎骏」→ 笔记本里改成宫崎骏。

**第五轮（v2.5）：偷懒日做成一个轻量的休息模式；能退出登录了。**

| 反馈 | 这一版的做法 |
|---|---|
| 用户没办法退出登录 | 左侧栏底部的头像打开「我的账号」：体验账号可以直接注册保留所有记录（原地升级，数据不动），所有账号都能退出登录；体验账号退出前会提醒「退出后就找不回来了」。手机上在「我的空间 → 设置 → 账号」。顺手修了一个全站的问题：确认弹窗（删除瞬间、收起愿望、退出登录等）之前点「确认」也会被当成取消 |
| 偷懒日几乎看不到了 | 偷懒日回到三个已有模块里，不新增第九个模块（见 3.8）：蜕变计划的「今天」顶部常驻一条「不用每一天都拼尽全力。[今天偷个懒]」；对话输入框旁边有月亮按钮；直接对小光说「今天想偷懒」也行 |
| 选了偷懒之后怎么办 | 小光接住：「收到！今天给自己放个假吧……需要我帮你调整一下计划吗？」，给三个选择：**今天休息，明天继续** / **这项任务有点难，想调整一下**（挑一件：调轻一档、先收起、让小光拆小）/ **不想做任务，想和小光聊聊天**。原因可选（有点累 / 心情不太好 / 今天太忙了 / 就是想歇歇），会留在休息记录里 |
| 宠物陪用户一起睡 | 偷懒日里，小芽闭上眼睛、慢慢呼吸、头上飘「z」：出现在计划页「今天」卡片、小光面板、成长页和偷懒弹层里 |

**第四轮（v2.4）：蜕变计划重新回到「计划」，轨迹放在计划上面。**
上一版把整个蜕变计划换成了日历式的记录表：只有一个愿望摆在终点，缺少走到那里的路，也没有和小光商量这条路的入口。这一版的做法：

| 反馈 | 这一版的做法 |
|---|---|
| 缺少走到愿望的路径；健身这类每天重复的事放不进「小步」 | 路径重新定义成三种东西：**里程碑**（路上看得见的站点，可带日期）、**习惯**（重复做的事，每天或每周 N 次，按周看进度）、**小步**（做一次就完成的事）。页面下半部分就是这条路：「今天」里有要打卡的习惯和待做的小步，右边是里程碑时间线 |
| 没有主动和小光沟通路径的入口 | 计划页有「和小光聊聊这条路」卡片：帮我规划这条路 / 这周怎么安排 / 我有点卡住了 / 看看我最近怎么样。点一下就带着这个愿望进入对话；小光先问一个问题，再用 `propose_plan` 给出一套里程碑 + 习惯 + 小步，**用户逐项勾选后才加入**，和路径上已有的重复项会被过滤掉 |
| 轨迹的逻辑：左下应是愿望定下的日子，右上应是计划实现的日子 | 曲线从「定下那天」画到「计划实现那天」（新建 / 编辑愿望时可改，快捷选 1 个月 / 3 个月 / 半年 / 1 年）。走过的部分实线发光，没走到的部分是虚线；「今天」有一个小标记；里程碑按日期插成小旗 |
| 节点卡片里应该是那天做过的事 | 时间节点 = 那天为这个愿望做过的事：完成的小步、习惯打卡、到达的里程碑、留下的瞬间。点开的卡片按天列出这些，再附上那天的好消息和休息日 |
| 90 天这样的长跨度点太多 | 按曲线的实际像素长度自动合并：保证相邻两个点至少隔 28px，依次尝试 1 / 2 / 3 / 7 / 14 / 30 天一组（桌面上 60 天的跨度是 3 天一个点），卡片底部写明「每个点是 3 天」 |
| 小人是火柴人、太出格 | 起点换成盘腿静坐的细线小人，终点是同一种笔触的愿景图形（心灵平静是水面上的太阳），都带一点柔光，跟随氛围配色 |
| 卡片里只有时间节点能点 | 起点、终点、做过事的日子、里程碑小旗可以点；小人、愿景图形、日期文字都只看不点。编辑入口移到卡片右上角的小按钮 |
| 侧栏要一句每 12 小时更新的鼓励语 | 小光面板顶部新增一张卡片：0 点和 12 点各换一次。最近 7 天有真实材料时由模型写一句「最近的你」（只用材料里的事实，禁用「不是……而是……」句式）；否则从一份核对过出处的名句里挑「送你一句」，按用户的愿望类别优先 |
| 好消息的三个按钮（收下星星 / 新发现 / 偷懒日）不直观 | 好消息只做两件事：**小确幸**（变成夜空里的一颗星）和**内心戏**（吐槽、碎碎念，以气泡显示）。一个「记下来」按钮，列表可按类型筛选。**休息日**移到蜕变计划的「今天」里：点「今天休息」，当天的习惯不用做，可以撤销 |
| 页面文字里「不是……」太多，AI 感重 | 页面、学堂文章、成长规则里的「不是……而是……」「不是结论」「不是完成度」等全部改成直接陈述；小光对话、主动消息、回顾信的提示词里都加了禁用这类句式的规则 |

**第三轮（v2.3）** 的内容保留并接进新的计划页：留下一个瞬间、阶段回望（改成在弹层里选 7 / 15 / 30 / 90 天）、小光的小发现、七类主题动效、对话里只提议瞬间。

**第二轮反馈（v2.2）**：「形象风格不统一，第一版简约一点，像 Grok 的 agent 那样统一；背景预设几个，适配不同人群。」

| 问题 | 这一版的做法 |
|---|---|
| 3D 贴纸各有各的脸、宠物是写实 3D、小光是扁平球，三套语言打架 | **一套角色语言**：小光是 Emotion Ball；宠物、植物、宝箱、星罐全部重画成扁平 SVG——圆身体、竖条小眼睛、淡腮红、纯色；28 张 3D 位图全部删除 |
| 界面装饰太多 | 导航、工具卡、任务、徽章、toast 统一成 **一套线性图标 + 彩色圆角方块**；版式参考 Muse：76px 图标轨 + 居中对话 + 小光面板 |
| 背景要适配不同人群 | **五种氛围预设**：森林夜（安静专注）/ 深空（极简夜猫）/ 晨光（清爽白天）/ 暖阳（需要被温柔鼓励）/ 海雾（容易紧张、想慢下来）。建档时选、选的时候整页当场切换；之后在左下角「氛围」或「我的空间 → 设置」随时换 |
| 想要个性但不要乱 | 小光只能换**颜色**（7 种，建档时也能选，选的时候提问的小光当场变色），形状和表情系统不变 |

**第一轮反馈（v2.1）** 的五条仍然保留：日终记忆整理、Emotion Ball 小光、按行为分化的宠物与进化图、覆盖 9 类功能的 27 枚徽章、点子与「一课」。动效（进化、徽章、宝箱、经验飞入、彩纸）也都保留，只是换成统一的扁平造型。

## 1. 创意：能做什么

### 1.1 产品愿景

**一句话**：小光是显化陪伴 agent——只帮你把「想成为的人」收成今天能走的一小步；不是万能助理。

答辩时可以用三层递进说清楚：

1. **比聊天机器人多一层状态**：它知道你今天有几件待做、宠物离分化还差 4 经验、你选过「中断时陪我找原因」。模型负责理解和表达，产品负责状态、记录和推进。
2. **比待办 App 少一层负担**：不需要维护系统。聊天里说一句「被老师夸了」，就落成好消息；夜里它再把当天值得留下的整理一遍。
3. **高光时刻是一个瞬间**：第 14 天，「播放回顾」把你以为它忘了的小事一页一页放出来——「原来你都记得」。

**能力边界**（写进系统提示，也写进产品）：可以目标拆解、习惯支持、情绪整理、一般生活建议、产品内记录与检索；不自称治疗师，不包办现实行动，不编造你的经历，不调用没接入的服务。

### 1.2 目标用户

主目标：**有具体愿望、但容易中断，并且一被评判就想放弃的人。** 学生的表达焦虑、年轻职场人的作息和健身，是最常见的两个入口。

核心动作因此放在**降低中断以后回来的成本**：休息日照样保留所有进度、中断时按你选的方式回应、「先放一放」的事随时能放回来。

次目标：**不写日记、但希望生活被看见的人**——好消息星空和夜里整理是为他们做的。
第三类：**喜欢养成和收集的人**——宠物分化和全功能徽章是为他们做的，但它们只记录真实行为，不鼓励刷分。

### 1.3 核心功能：八个模块，一个入口

八个模块分三组排布，不做八个同权重标签：

| 组 | 模块 | 用户拿到什么 |
|---|---|---|
| 陪你 | 对话 | 唯一的人格主体；工具结果落成带图标的卡片 |
| 陪你 | 蜕变计划 | 每个愿望：一条从定下那天到计划实现那天的轨迹 + 一条路（里程碑 · 习惯 · 小步）；可以和小光一起规划 |
| 陪你 | 好消息 | 小确幸变成夜空里的星星，内心戏是一个个小气泡 |
| 陪你 | 成长进化 | 宠物舞台、进化图、亲和度、29 枚徽章、经验账本 |
| 探索 | 点子 | 6 个可玩场景，点一下进入「一课」 |
| 探索 | 心灵学堂 | 8 篇团队内容，书封卡片；小光只读、只解释 |
| 探索 | 蜕变报告 | 14 / 30 天；全屏故事模式 + 可核对来源 + 分享预览 |
| 探索 | 我的空间 | 档案、记忆（含修订记录）、夜里整理、时间线、设置 |

**主动关怀**是横向机制：站内消息出现在右侧「小窝」和对话线程里，23:00–08:00 不打扰，频率可调。

### 1.4 成长系统（重新设计）

**宠物线**（独立于小光，不随等级改变小光的样子）：

```
光蛋 ──(100)── 团子 ──(310 · 分化)──┬── 小焰 ──(650)── 焰尾狐   行动最多
                                   ├── 花苞 ────────── 花角鹿   好消息最多
                                   ├── 云朵 ────────── 云鲸     练习最多
                                   └── ？？？ ──────── ？？？   三样都不偏科（隐藏形态）
```

- **分化不是手选的，是你做出来的**：310 经验那一刻，看行动 / 好消息 / 练习三类累计经验的比例。之前一直能看到「它在往哪边长」的亲和度条，想换方向，就多做另一类事。
- **一眼看得清**：进化图把整条路线摊开；走过的节点点亮，正在偏向的分支用流动虚线和「可能是它」标出，其余是剪影，隐藏形态只有问号。路线清楚，结果保留悬念。
- **数字规则**沿用讨论稿：行动 +10、好消息 +6、练习 +12、每天第一次来聊 +8；每类每天 30、总共 120；按「来源 + 引用」去重，同一件事永远只计一次；每 40 经验升一级。
- **今日任务**就是这四类来源：四件都做到，宝箱打开（纯庆祝，不额外加经验，守住 120 上限）。

**徽章**（29 枚，9 类）：

| 类 | 例子 |
|---|---|
| 对话 | 第一句话 · 话匣子（30 句） |
| 计划 | 第一步 · 七次落地 · 习惯成形（30 步） |
| 好消息 | 第一颗星 · 收集星星（10）· 星罐满了（30）· 内心戏（第一段内心戏） |
| 练习 | 静下来 · 练习者（5 次）· 重新认识 · 都试过了（4 种场景） |
| 记忆 | 记住我（第一次让它记住）· 说清楚（确认 / 否定 / 修改一条记忆）· 被好好整理（第一次夜里整理） |
| 学堂 | 开卷 · 求知（5 篇） |
| 报告 | 回头看（打开一次报告） |
| 陪伴 | 好好休息（第一次休息日）· 回来了（休息之后又完成一步或一次打卡）· 一周 · 半个月 · 一个月 |
| 成长 | 破壳 · 分化 · 长大了 · 隐藏形态（未获得前名字是问号） |

「休息也算」「回来了」是刻意放进去的：中断本身也被看见，而不是只奖励连续。

### 1.5 与讨论稿的偏离（及原因）

| 讨论稿 | 这一版 | 原因 |
|---|---|---|
| 宠物从细胞→蝌蚪→乌龟→山海经 | 光蛋→团子→四分支→成年 | 按反馈去掉山海经；分支由行为决定，比单向链条更能说清「你的选择留下痕迹」 |
| 建档 8 题含「选一个它的气质」 | 去掉这一题，换成「中断时希望我怎么做」 | 小光形象固定（v0.3 共识），选气质已没有意义；中断偏好则贯穿整个产品 |
| 「现在小光有多了解我」做成展示页 | 直接交给真实对话 | 让模型基于真实记忆说出「记得的」和「不确定的」，比静态列表更像讨论稿描述的体验 |
| 14 / 30 天报告 | 保留，并加「播放回顾」故事模式；未满天数时也能看当下回顾 | 初赛评委看不到第 14 天，核心功能不能在 demo 里不可见 |

## 2. 技术：怎么落地

### 2.1 Agent 架构

一个主 Agent + 按需工具 + 确定性业务流程，不做多 Agent 编排。

```
浏览器（原生 ES 模块，无构建步骤）
 ├ 对话 ── SSE ──▶ /api/chat ─▶ agent.chat()
 │                               1 每天第一句 → 签到经验（幂等）
 │                               2 检索记忆（FTS5 二元组 + 新近度 + 类型权重）
 │                               3 系统提示 = 人设 + 核心档案 + 中断偏好 + 检索结果 + 成长规则
 │                               4 流式调用模型，带 11 个工具（≤4 轮），每个工具返回真实回执
 │                               5 表情事件（mood）→ 前端 Emotion Ball
 ├ 成长 ─────── growth.py：账本 / 上限 / 去重 / 分化 / 徽章 / 一次性庆祝标记
 ├ 学堂 ─────── academy.py：只读
 ├ 报告 ─────── 规则算事实与节点 → 模型只润色那封信
 └ 后台线程（每 10 分钟）
      ├ 03:00 后：为每个用户整理「昨天」（digest.py）
      └ 主动消息：空闲 ≥ N 小时、静默时段不发、一次最多一条未读
```

**原则：模型只能提议，不能记账。** 经验只由 `growth.award()` 写；报告里的数字由 SQL 算；学堂只有读函数；庆祝动画只在后端给出一次性标记（`evolved` / `badges_new`）时出现，前端不自己「演」。

### 2.2 模型选择

主对话：ModelFlare `gpt-6.1-sol`（OpenAI 兼容，`reasoning_effort=low`），密钥只在服务器 `.env`。
美术素材：openlux `gpt-image-1.5`（原生透明背景）。实测 `gpt-image-2` 在这个中转上返回 RGB 加假棋盘格，无法叠层；`flux-1.1-pro` 当时 503。

本版用真实模型跑了讨论稿的关键场景（本机，2026-10-27）：

| 用户说 | 实际行为 |
|---|---|
| 帮我记住我喜欢吃寿司 | 调 `remember`，立即写入受保护记忆 |
| 我三天没健身了 | 不写任何记忆；回复「也不等于你没毅力。你愿意和我一起看看，这几天是哪里卡住了吗？」（照「一起找原因」偏好） |
| 其实我现在不喜欢寿司了 | 调 `correct_memory`：旧文本、新文本、用户原话一起存进修订记录 |
| （夜里整理） | 新增事件「10月27日：连续三天没健身」——带日期的事件，没有性格标签 |
| 我什么时候能进化 | 调 `get_growth`，回答 306 / 差 4 / 分化规则，与数据库一致 |
| 水桶效应是什么意思 | 调 `knowledge_search`，只引用学堂文章 |

**一个被实测抓到的问题**：第一次运行时模型对「我三天没健身了」也调了 `remember`。提示词约束不够可靠，所以加了**服务端硬约束**：用户这句话里没有「记住 / 别忘 / 记一下」这类明确请求时，`remember` 直接拒绝，近况交给夜里整理。有测试覆盖。

**降级**：模型不可用时，聊天说「连不上了」，报告用模板信，夜里整理只写模板小结、不动任何记忆；计划、好消息、学堂、成长全部照常可用。

### 2.3 长期记忆

| 类型 | 存哪 | 何时写 | 谁能改 |
|---|---|---|---|
| 核心画像 | `profile` | 建档 / 我的空间 / 偏好工具 | 字段级，用户可改 |
| 明确记忆（受保护） | `memory`，source = `chat:explicit` / `confirmed` / `onboarding` | 「帮我记住」时立即写 | 用户；或用户当天原话里能逐字找到依据的整理 |
| 推测 | `memory`，status = `guess` | 夜里整理，每天最多 1 条 | 不用于理解用户，直到用户点「对」 |
| 事件与新发现 | `memory`，source = `digest` | 夜里整理 | 整理可更新 |
| 业务数据 | 步骤 / 好消息 / 经验 / 场景 / 徽章各自的表 | 工具或页面操作 | 只经由后端规则 |

**夜里整理**（`core/digest.py`）：

1. 取这一天的对话、好消息、完成的小步、练习；超过 1200 字的粘贴文本标成「长文资料」，不当作用户的经历。
2. 模型只输出**增量**（ADD / UPDATE / DELETE），不重写整份画像。
3. 改动受保护记忆时，必须给出用户当天的原话；**后端逐字核对**，对不上就拒绝，拒绝也会记下来。
4. 推测最多 1 条，以待确认状态进入。
5. 每次改动都写一条修订记录（旧文本、新文本、原因、依据），「我的空间 → 记忆 → 修订记录」可以看到。
6. 写一条当天小结和最多 3 个瞬间，「夜里整理」页按天展示。

7. 同一次调用顺手更新「笔记本」：在上一版基础上合并今天值得长期记住的内容，分「最近的生活 / 在意的人 / 正在努力的事 / 心情和状态 / 相处时的偏好 / 时间线」，≤1200 字，推测标「（猜）」。用户改过的版本会作为下一晚的起点。

调度：后台线程每 10 分钟检查一次，03:00 之后为「昨天」整理，每人每天一次（可在例行任务里关掉）。演示时可以在「夜里整理」页点「现在整理一下今天」。

**对话上下文分三层**（`core/agent.py`）：

| 层 | 内容 | 放在哪 |
|---|---|---|
| 最近 | 最近 72 小时的全部对话原文（每天第一句标日期），上限 24000 字；不足 16 轮时补足 16 轮；单条超长粘贴截到 1500 字 | 对话历史 |
| 中期 | 早于 72 小时的最近 7 天每日小结 | system prompt |
| 长期 | 小光的笔记本 + 核心画像 + 和这句话相关的记忆（检索）；需要原话时用 `search_chats` 翻全部旧聊天（关键词 + 中文两字片段打分） | system prompt / 工具 |

为了让长上下文能被缓存复用，每轮都在变的部分（当前时间、本句检索到的记忆）单独放在最后一条 system 消息里，前面的人设、画像、笔记本、历史对话按时间只增不改。

**检索**仍是 SQLite FTS5（中文二元组）× 新近度衰减 × 类型权重，没有向量层（见第 4 节）。

### 2.4 工具调用

| 工具 | 读 / 写 | 约束 |
|---|---|---|
| `search_memory` | 读 | — |
| `remember` | 写（受保护） | **用户必须明确要求**，否则服务端拒绝 |
| `correct_memory` | 改 / 删 | 必须附用户原话，写修订记录 |
| `add_step` / `complete_step` | 写 | 完成按 `step:<id>` 计分，幂等 |
| `propose_plan` | **只提议，不写** | 为某个愿望提议 ≤3 里程碑、≤3 习惯、≤3 小步；服务端先过滤掉路径上已有的项；对话卡片里勾选后才调用 `/api/plan/apply` |
| `add_habit` / `checkin_habit` | 写 | 只在用户明确要求时加习惯；打卡按 `habit:<id>:<日期>` 计「行动」经验，撤销再打不重复计分 |
| `log_good_news` / `log_lazy_day` | 写 | 小确幸按 `rec:<id>` 计分；偷懒日一天只记一次，可带原因；之后小光不推荐任务 |
| `schedule_task` / `edit_task` | 写 | 一次（几分钟后 / 某天某时）、每天、工作日、每周几；remind 到点发模板句不调模型，ai 到点由小光按 TA 的情况和计划里要留意的事写一条；每人最多同时开 20 个；`edit_task` 关掉 / 打开 / 删掉 / 改时间 |
| `edit_plan` | 写（要同意） | 愿望 / 里程碑 / 习惯 / 小步 / 瞬间的 add / change / remove / restore；名字对不上就返回现有名单，不会改到别的项上 |
| `look_up` / `app_guide` | **只读** | 按功能读用户的真实数据（带 id）/ 读功能说明 |
| `edit_good_news` / `update_settings` | 写（要同意） | 改、删好消息；改设置和画像，枚举校验 |
| `update_notebook` | 写 | 只在用户明确要求时：往笔记本里加 / 改 / 删；加的内容同时记成一条受保护记忆 |
| `search_chats` | **只读** | 在全部旧聊天里按关键词找原话；找不到就照实说 |
| `adjust_habit` | 写 | 只在用户明确说某个习惯太难时：调低一档频率（每天 → 每周 3 → 2 → 1 次）或先收起 |
| `propose_moment` | **只提议，不写** | 返回待确认的草稿；界面卡片上用户选愿望、点「留下」才调用 `/api/moment` 保存 |
| `get_growth` | 读 | 读取时不消费庆祝标记，留给界面 |
| `knowledge_search` | **只读** | 没命中就说没命中 |
| `start_scene` | 写 | 前端随即打开「一课」 |

|---|---|---|
| 测试 | 28 个端到端测试全部通过（真服务器 + 脚本化假模型） | `python -m unittest discover -s demo/tests` |
| 数据隔离 | 每用户一个 SQLite 文件；身份只来自 HttpOnly 会话 | 测试：A 的好消息不出现在 B 的任何接口 |
| 经验规则 | 每类 30 / 每日 120 / 去重 | 测试：连续完成 5 步得 10,10,10,0,0 |
| 分化与庆祝 | 按亲和度分化；进化和徽章各只报一次 | 测试覆盖 |
| 受保护记忆 | 没有原话依据就拒绝修改 | 测试：伪造的 UPDATE / DELETE 被拒 3 条 |
| 首字延迟 / 成本 | **未做统计** | 需要日志聚合 |
| 记忆命中率 | **未做真实用户评测** | 需要 5–10 名种子用户 |

### 2.6 产品落地

- 部署：单机 Python 标准库 + 每用户 SQLite + systemd + Caddy；`bash deploy/deploy.sh` 一条命令打包、备份、替换、重启、自检，并给出回滚命令。
- 前端零构建：原生 ES 模块，Emotion Ball 以普通脚本加载。
- 字体：源流圆体 CN（SIL OFL）按 Unicode 区段切成 14 片，按字频排序，页面只下载用到的片；拉丁字母和数字用 Nunito。共 2.6 MB，但单页通常只取 1–3 片（约 180–350 KB）。脚本：`tools/build_fonts.py`。
- 素材：**零位图**。小光是 Emotion Ball（SVG），宠物 / 植物 / 宝箱 / 星罐是代码画的扁平 SVG（`public/js/pet.js`），图标是一套线性 SVG（`public/js/ui.js`）。颜色全部来自主题变量，所以五种氛围下都能正确显示，剪影、发光也只是换一个填充变量。

### 2.7 可行性：定时任务与更长的对话记忆

**定时任务会不会压垮服务器？不会。** 所有用户的任务放在一张中心表 `data/tasks.db`，按 `(enabled, run_at)` 建索引。调度线程每 30 秒只做一次「有没有到点的」索引查询，到点的任务才去打开对应用户的库写一条消息，然后算出下一次时间。没有任务到点时成本就是一条查询；1 万个任务也是毫秒级。提醒类（remind）不调模型，零 token；「到点让小光说点什么」（ai）每次 1 次模型调用（约 3–4k 输入 token）。网页端每 30 秒调一次 `/api/pulse`（只读两个计数），有新消息才拉完整数据。

**更长的对话记忆要多花多少？** 在示例账号上实测（中文约 1 字 ≈ 0.7–1 token）：

| | system prompt | 工具定义 | 历史对话 | 每次请求约 |
|---|---|---|---|---|
| 之前（最近 32 条） | ~4000 字 | ~6600 字符 | ~2000–3000 字 | 7–8k token |
| 现在 · 普通用户（3 天约 90 条 × 60 字） | ~4000 字 + 笔记本 ~600 字 | 同上 | ~5000 字 | 约 10k token |
| 现在 · 重度用户（3 天 180 条，实测 14475 字） | 同上 | 同上 | ~14500 字 | 约 17k token |
| 上限（24000 字封顶） | 同上 | 同上 | 24000 字 | 约 24k token |

带工具的回合会发两次请求（工具调用 + 回复），输入翻倍，但第二次与第一次前缀完全相同，可以命中提示缓存。夜里整理把笔记本合并进原来那一次调用，只多约 1.5k 输入、1k 输出 token / 人 / 晚。结论：普通用户每轮成本约为原来的 1.3 倍，重度用户约 2–3 倍并有硬上限；换来的是「记得这三天说过的每句话」，以及通过笔记本和 `search_chats` 记得更早的事。若成本成为问题，先调 `HISTORY_CHARS`，再考虑把第 2–3 天的原话换成更细的分时段小结。

**仍然不够的地方**：定时提醒只在网页里出现（开着网页时有浏览器通知），关掉网页后没有手机推送——要做到需要 PWA + Web Push（VAPID）或原生 App，列在第 4 节。

## 3. UI：用户体验

### 3.1 视觉原则：一套语言，五种氛围

- **角色只有一种造型语言**：圆润的身体、竖条小眼睛、淡腮红、纯色、不画写实纹理。小光（Emotion Ball）、宠物的 10 个形态、消息头像、toast 头像都遵守它——用户在任何地方看到的都是「同一家人」。
- **界面装饰只有一种**：线性图标（1.8px 描边、圆头）+ 彩色圆角方块。七个分类色（橙 / 柠檬 / 薄荷 / 天蓝 / 紫 / 珊瑚 / 粉）固定用在固定的含义上：行动橙、好消息柠檬、练习薄荷、对话天蓝、记忆紫、学堂珊瑚、报告粉。
- **字体圆润**：中文源流圆体（500 / 700），拉丁字母和数字 Nunito；大数字会滚动。
- **按钮可以「按下去」**：底部 3px 厚边，按下时整块下沉（多邻国的手感，但颜色跟随氛围）。

### 3.2 五种氛围预设

| 氛围 | 适合 | 背景 | 主色 / 小光默认色 |
|---|---|---|---|
| 森林夜 | 想安静下来、专注的人 | 深绿渐变 + 斜射光 + 光尘 + 远山 | 灯黄 |
| 深空 | 喜欢极简、常在夜里聊天的人 | 近黑 + 顶部一点紫光（接近 Muse / Grok 的深色） | 月白按钮 · 薰衣草强调 |
| 晨光 | 白天用、喜欢清爽干净的人 | 近白纸色 + 两团极淡的光晕 | 墨黑按钮 · 薰衣草强调 |
| 暖阳 | 需要被温柔鼓励的人 | 暖桃渐变 + 慢慢呼吸的太阳 | 珊瑚 |
| 海雾 | 容易紧张、想慢下来的人 | 雾蓝渐变 + 缓慢的波 | 海蓝 |

实现：每种氛围只是一组 CSS 变量（底色、表面、线、文字四级、按钮、强调、完成色、剪影色等）+ 一组背景装饰层；组件里不写死任何颜色。首帧之前就套上上次的选择（`js/boot-theme.js`），浅色主题不会先闪一下深色。登录前存在浏览器，登录后写进画像（跨设备）。

### 3.4 Agent 形象

- **小光 = Emotion Ball**（blob）。颜色跟随氛围或用户选择；右侧面板里是大号的、实时换表情的小光，名字下有一行状态（「在听你说」「在翻我们的回忆」「正在回你」「写好了」）；眼睛跟着鼠标；点它会跳一下。消息头像和 toast 用同一颗球的静态快照，所以全站只有一个形象。
- **授权**：Emotion Ball 的引擎非商业免费，**球形角色外观永不商用**。本 demo 用于竞赛展示，入口页有署名；商用前换成自研形象，只改 `public/js/ball.js`。宠物是我们自己画的 SVG，不受这条限制。
- **宠物与小光分开**：成长只发生在宠物身上，小光的样子不变。
- **性格**：形象不变，说话方式有三种——温柔（先接住情绪，慢慢说）、有条理（帮你把事情理清楚）、活泼（轻松一点，偶尔逗你笑）。只改提示词里的一段「你的性格」，记得的事、能做的事都一样。

**三种路径元素**

| | 是什么 | 例子 | 怎么完成 | 经验 |
|---|---|---|---|---|
| 里程碑 | 路上看得见的站点，可带日期，会作为小旗出现在轨迹上 | 能连续跑 5 公里 | 点圆点标记「到达」，可改回 | 行动 +10（`ms:<id>`） |
| 习惯 | 重复做的事：每天，或每周 1–6 次；按周（周一开始）显示进度和 7 个小圆点 | 每周去健身房 3 次 | 每天点一次打卡，可撤销 | 行动 +10（`habit:<id>:<日期>`，撤销再打不重复计） |
| 小步 | 做一次就完成的事，5 分钟内能开始 | 办好健身卡 | 打勾；「先放一放」随时放回 | 行动 +10（`step:<id>`） |

休息日：「今天」里点「今天休息」→ 当天的习惯不用做，周进度、经验、宠物都不受影响，可以撤销；轨迹卡片里那天会写「这天给自己放了假」。

**轨迹规则**

| 规则 | 实现 |
|---|---|
| 起点 / 终点 | 起点是愿望定下的日子（有更早的补记时取更早那天），终点是计划实现的日子；计划日过了，终点延到今天，并提示可以换个日子 |
| 时间映射 | 起点到终点的日历天数均匀铺在曲线弧长上；曲线按舞台的真实像素生成，宽屏窄屏都不变形，窗口变化时重画 |
| 节点 | 某天为这个愿望做过事（小步 / 打卡 / 里程碑 / 瞬间）就有节点；落在起点那一组并进起点，靠近终点的并进终点 |
| 合并 | 相邻节点至少隔 28px：依次试 1 / 2 / 3 / 7 / 14 / 30 天一组，点画在组的中间日 |
| 可点的只有时间节点 | 起点卡片：「这一天，你定下了……」+ 出发时的自己；终点卡片：计划日、向往的样子、还剩几天和几个里程碑；普通节点：按天列出做过的事、瞬间（可编辑删除）、那天的好消息 |
| 动效 | 点节点先播本愿望的主题动效（水波 / 金点 / 伸展 / 星星 / 连线 / 开窗 / 光晕），再打开卡片；「减少动态效果」下只留静态光晕 |

**和小光一起规划**：四个入口都会带着愿望名称和计划日期进入对话。提示词要求小光先看路径上已有什么，第一次只问一个问题、不调用工具；信息够了再 `propose_plan`。服务端再做一次去重（忽略空格和标点，较长的标题互相包含也算重复），对话卡片里每项都有勾选框，点「加进计划」才写入。线上用真实模型走过一遍：第一句问了「最卡你的是开口前的紧张，还是持续练习」，第二轮的提议跳过了路径上已有的两个里程碑和习惯，勾掉一项后加入了 1 个里程碑、1 个习惯、2 个小步。

**数据**：`wish` 增加 `target_day`；新表 `habit`（愿望、标题、每天 / 每周 N 次、是否收起）、`habit_log`（习惯 + 日期唯一）、`milestone`（标题、日期、状态、到达时间）。`moment` / `insight` / `reflection` 沿用 v2.3。全部在每个用户自己的 SQLite 里，导出接口一并导出。体验账号预置：两个愿望各有计划日，三个带打卡历史的习惯（今天留给访客自己打）、四个里程碑（一个已到达），历史打卡不补经验，保持 306 经验的进化演示。

**侧栏鼓励语**（`core/cheer.py`）：每天 0 点、12 点各一个时段。进入新时段时先立刻给一句名句（18 句，都核对过出处，比如苏轼《定风波》、荀子《劝学》、王维《终南别业》），最近 7 天有至少两条真实材料时，后台再请模型改写成一句「最近的你」；模型输出里出现「不是」就丢弃，时段已过也丢弃。

### 3.8 偷懒日：一个没有负担的休息模式

```
 今天 10月29日 周四                         今天 10月29日 周四 · 偷懒日 · 暂停中
 ┌ 不用每一天都拼尽全力。 [☾ 今天偷个懒] ┐   ┌ (睡着的小芽 z z) 今天是偷懒日 · 有点累            ┐
```

| 位置 | 做什么 |
|---|---|
| 蜕变计划 · 今天 | 一键偷懒（整天）；每个习惯旁边的月亮按钮是「这一项今天先不做」（单项暂停，做了就自动取消）；偷懒日卡片里可以调整计划、去聊天、取消偷懒；第二天会说「昨天好好歇了一天，小芽也睡饱了。今天从哪件小事开始？」 |
| 小光 | 说「今天想偷懒」→ `log_lazy_day`，卡片上给出「明天继续 / 调整一下计划 / 就想聊聊天」；说「这个习惯太难了」→ `adjust_habit`；偷懒日当天提示词要求小光不推荐任务、不提醒要做的事；定时主动消息在偷懒日不发 |
| 面板 · 成长 | 小芽睡觉；今日任务里「行动」这项显示「今天偷懒，行动先暂停」，算作完成（不加经验），宝箱照样能开 |
| 我的空间 · 报告 | 时间线里记一条「今天偷个懒：有点累」；报告里有「慢下来的日子」节点（「这些天你好好休息了，所有进度都还在」）；轨迹节点卡片里写「这天给自己放了假」 |

数据：整天偷懒仍是 `record(type=rest)`，一天一条、可撤销；单项暂停是新表 `habit_skip(habit_id, day)`。所有休息都不扣经验、不影响习惯的周进度和宠物。

## 4. 没做到 / 不知道的（诚实清单）

1. **记忆检索没有向量层**：中文同义改写召回弱，没有做真实用户的命中率评测。
2. **主动消息与夜里整理靠 10 分钟轮询、例行任务靠 30 秒轮询**，都是进程内线程，没有独立的任务队列；提醒只在网页里出现（开着网页时有浏览器通知），关掉网页后没有手机推送（需要 PWA + Web Push 或原生 App）。
3. **延迟与成本没有 p95 统计**，只有单次实测；2.7 的 token 估算基于示例账号与模拟的重度用户，没有真实用户数据。
4. **蜕变计划还没做用户测试**：轨迹的起止逻辑、节点合并、习惯 / 小步 / 里程碑三分法是否好懂，都需要真人测；身体 / 财务数据、自定义角色、图片与音频、分享都未做。习惯暂不支持「每周固定周几」和提醒推送。
   鼓励语在一个时段内只换一次：新账号第一个时段一定是名句，有了材料后要等到下一个时段才会出现「最近的你」。
5. **宠物图鉴只记录当前路线**：选定分支后，看不到「如果当初偏向另一边会是什么」，也还没有图鉴收集。
6. **30 天报告**和 14 天共用版式，没有单独的视觉模板。
7. **分享只到「复制文字版」**，还不能导出图片卡。
8. **Emotion Ball 不能商用**：正式产品前必须换成自研形象（只需改 `ball.js`）。
9. **字体总量 2.6 MB**：按需加载后单页通常 1–3 片，但首次访问在慢网络下仍需要几百 KB。
10. 语音、移动 App、AI 生成的定制宠物：未做，也不在初赛范围。
11. **偷懒日的后续**：休息保护道具、宠物更多睡觉动画、个人休息规律分析都还没做；「调轻一档」只改频率，不会自动拆小任务（拆小要去对话里让小光提议）。

## 5. 答辩演示顺序（约 8 分钟）

1. 打开线上 → 先点一下入口页的五种氛围（整页当场切换）→ 「先体验一下」。
2. 对话：说「帮我记住我喜欢吃寿司」→ 记忆卡片；再说「我三天没健身了」→ 不贴标签、按偏好陪你找原因；再说「其实我现在不喜欢寿司了」→ 更正卡片。
3. 我的空间 → 记忆 → 修订记录：能看到旧说法、新说法和用户原话。
4. 我的空间 → 夜里整理 → 「现在整理一下今天」：三天没健身被记成带日期的事件。
5. 成长进化：306 经验、差 4 分化、进化图上正在偏向焰尾狐。
6. 蜕变计划：看「自信与表达」——起点的小人、终点的愿景、已走的实线和没走的虚线 → 点一个节点（星星绽开 → 那几天的打卡、小步和原话）→ 点起点和终点 → 在「今天」里给「跟读英文播客」打卡 → 新的点亮起，经验飞进顶栏 → **全屏进化成「小焰」**。
   再点「和小光聊聊这条路 → 帮我规划这条路」：小光先问一个问题，回答后给出一套可勾选的里程碑 / 习惯 / 小步，勾掉一项，点「加进计划」，回到计划页就能看到。
   右侧面板顶部是这个时段的「最近的你」。好消息页：记一件小确幸（星星亮起）和一段内心戏（气泡）。
   回到「今天」，点「今天偷个懒」→ 选「有点累」和「这项任务有点难」→ 把一个习惯调轻一档 → 卡片变成睡着的小芽，面板和成长页的小芽也睡了。
   对话里说「1 分钟后提醒我喝口水」→ 面板「例行任务」里多了一条 → 一分钟后小光在对话里提醒，并弹出浏览器通知。再问「还记得我上周说过 Mia 的什么事吗」→ 小光翻旧聊天回答。
   左下角头像 → 我的空间 → 夜里整理，看小光记的关于你的笔记；点名字旁的铅笔改个称呼；设置里把性格换成「活泼」再聊一句；最后在设置 → 账号里退出登录。手机上打开同一个网址，演示左上角的抽屉。
7. 点子 → 今日推荐 → 「一课」全屏问答 → 完成页。
8. 蜕变报告 → 「播放回顾」故事模式 → 分享预览只公开你勾的内容。
9. 最后用两个浏览器登录两个账号，证明数据互不可见。
