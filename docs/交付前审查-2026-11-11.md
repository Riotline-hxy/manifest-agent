## 一、系统与数据流

```
浏览器（原生 JS / SVG / PWA，sw.js 只管推送，不缓存页面）
   │ cookie 会话（HttpOnly；用户 id 只从会话取）
   ▼
server.py（标准库 HTTP，线程池）── 静态文件（ETag）
   │ routes.py：约 60 个接口；大多数写操作做完后返回整页数据 bootstrap
   ├─ /api/chat（SSE）→ agent.chat
   │      ├─ 上下文：人设与示范 + App 地图 + 计划全貌 + 固定要点 + 笔记本 + 最近三天原话 + 这句话检索到的记忆
   │      ├─ 并行：router.decide（一次小调用，判断「TA 这句是不是要现在做一件事」）
   │      ├─ 主模型流式回复，最多 4 轮工具（24 个工具，写入类在代码里再查一遍许可）
   │      └─ acts：每个动作变成 推荐 / 回执（可撤销）/ 待确认 三种卡片，存进消息
   ├─ 点子：scenes（冥想、感恩）· flows（显化你的愿望、调整现有计划）· kickstart（两分钟启动）· topics
   ├─ growth / town：经验、金币、每日任务、小镇，全部后端记账，按 ref 去重
   └─ 后台线程 scheduler：03:00 后 digest（每天的记忆整理）→ finds（小光的发现）→ weekly（一周一页）→ 主动消息；另一条线程跑定时任务
存储：data/auth.db（账号、会话）· data/u/<uid>/mind.db（每人一库）+ photos/ · tasks.db · push.db · metrics.db
```

### C. 风险推测（没有复现或没条件验证）

- **夜里整理是串行的**：所有用户在一个线程里依次整理，每人一次最长 90 秒的模型调用，主动消息也在同一个循环里。用户到几百人后，03:00 开始的这一轮会拖很久，早上的主动消息会晚到。
- **nginx 配置不在仓库里**：第 8 条的修复假设 nginx 和服务在同一台机器、前面没有 CDN。前面还有一层 CDN 时要设 `MANIFEST_PROXY_HOPS=2`，否则所有用户会被当成同一个地址一起限流。
- **推送白名单可能漏掉小众浏览器**：只放行了 Chrome / Edge（FCM）、Firefox、Safari、旧版 Edge 的推送服务。遇到别的用 `MANIFEST_PUSH_HOSTS` 加。
- **iPhone 输入框放大**：所有输入框字号是 13–15.5px，iOS Safari 在小于 16px 时点进去会放大页面。已加 iOS 专用规则提到 16px（`public/css/base.css` 末尾），**没有真机验证**。

### D. 体验与产品建议

- 用户没有自助的「导出我的数据」「删除账号」入口（导出接口有，界面没接；删除只有后台能做）。
- 三分钟感恩是「答完就写」，问答直接进聊天记录，中途关掉也留着。另外四个练习都是确认后才存，这一个不一致。
- 两分钟启动不勾「让小光记住」时，任务名仍会进「动态」时间线，和「什么都不留」的说法有出入。
- 模型两次都不开口时的兜底回复（「弄好了，在下面。」等三句）是我写的，极少出现，语气请产品负责人过目。

## 六、记忆与上下文：下一步的方向（没有实现）

针对 flash 这一档模型，按收益排序：

1. **记忆不多时不做检索，直接给一份完整的档案。** 现在同一件事有三份：固定要点（≤700 字）、每轮词面检索（≤6 条）、笔记本（模型每晚重写的 ≤1600 字）。词面检索靠两字片段对上，实测多半对不上或对错（第 20 条）。多数用户的活跃记忆在几十条、两千字以内，可以按「了解你」的六类排成一份档案整份放进系统提示（稳定，能命中缓存），超过预算再对「最近发生的事」做检索。笔记本只留时间线和近况，不再重复要点。
2. **工具定义瘦身。** 24 个工具共 1.2 万字，和系统提示一样大。`add_habit`、`add_step`、`adjust_habit` 和 `edit_plan` 功能重叠；`update_settings`、`look_up`、`edit_plan` 三个最大。合并或按路由结果只给相关工具，能同时降首字时间和选错工具的机会。
3. **功能说明**：`guide.py` 的地图每轮都在（663 字），细节按需查，这个结构不用动。这一轮只更正了一处位置。

这三项都会影响回复质量，需要三种性格的全量评测加人工读回复才能定，所以没有在这一轮动。

## 七、需要你决定的事

1. **是否合并这个分支。** 行为上最明显的两处变化：删除更保守（用描述而不是名字指代时，比如「把那个早起的习惯删了」，会多问一句）；什么时候提议留瞬间改由主对话自己判断，不再由路由强制。
2. **「忘掉」要不要连修订记录一起清**（第 19 条）。
3. **首字时间要不要专门做一轮**（第 17 条和上面第六节）。
4. **路由要不要继续保留。** 它每轮多一次调用。这批评测里主模型自己基本都能调对工具，路由真正改变结果的只有少数几次，而且有判错的时候。去掉之前需要专门测「嘴上说做了、其实没调工具」的发生率。
5. **照片备份**（第 18 条）和**备份清理**（第 22 条）怎么做。
6. **感恩练习要不要也改成确认后保存**，要不要加自助导出 / 删除账号。
