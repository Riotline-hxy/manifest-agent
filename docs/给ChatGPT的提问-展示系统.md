# 给 ChatGPT 的提问：AI 陪伴 App 里「卡片 / 回执」的展示方式

（整段复制给 ChatGPT，打开联网搜索）

---

我在做一个中文的 AI 陪伴 App。用户像发微信一样和 AI 朋友「小光」聊天，小光可以在聊天里替用户做事：推荐 App 里的功能（冥想、两分钟启动、三分钟感恩、读一篇文章），改用户的计划（小步、里程碑、习惯），记录小确幸 / 内心戏，提议把一个瞬间留在成长轨迹上（要用户点头才保存）。

我想给这些动作设计一套**统一、简约、直观**的展示方式，只分三类：
1. **推荐**：小光建议试一个功能，给出入口（按钮 + 一句介绍）。所有功能的入口必须同样大小、同样布局。
2. **回执**：小光已经做了一件事（改了小步名字、记了一条小确幸），要让用户一眼看出改了什么，最好能撤销。
3. **待确认**：小光提议，用户点「留下 / 不用」才生效。

我们目前倾向的方案是：回执是气泡下面一行细签条（例如「✎ 小步 ~~旧名字~~ → 新名字 · 撤销」），推荐是固定高度的一行（图标 + 名字 + 一句介绍 + 开始按钮）。

请你联网查一下，**有没有经过市场验证的产品或设计规范在做类似的事**，帮我判断我们的方向对不对、有没有更好的做法。重点看：
- AI 聊天 / 陪伴 / 助手类产品里，AI 执行了操作后是怎么展示回执的。比如 ChatGPT（记忆更新、任务、Canvas）、Claude（工具调用、Artifacts）、Gemini、Pi、Replika、Character.AI、豆包、Kimi、元宝、Apple Intelligence / Siri、Google Assistant 等。
- 消息类产品里的「富卡片 / 快捷操作」规范，比如 Slack Block Kit、Microsoft Adaptive Cards、Telegram / WhatsApp / LINE 的按钮消息、微信的服务卡片、iMessage App。
- 生产力工具里「AI 改了你的数据」的展示：Notion AI、Linear、Todoist、Things、Google Calendar 的撤销提示（undo snackbar）等。
- 有没有关于「AI 动作透明度 / 可撤销」的设计指南，比如 Google People + AI Guidebook、Microsoft HAX Toolkit、Apple HIG 里和 AI 相关的部分。

请这样回答（尽量简短）：
1. 找到的 5–8 个最相关的做法：每个一两句说清怎么展示，附**来源链接**，标明是官方文档、截图、评测文章还是论坛说法。
2. 这些做法里反复出现的共同规律（3–5 条）。
3. 对照我们的方案：哪些地方和成熟做法一致，哪些地方可能有问题，有没有值得直接借鉴的细节（比如撤销放多久、改动怎么合并、推荐一次给几个）。
4. 找不到可靠来源的就直说，不要编。
